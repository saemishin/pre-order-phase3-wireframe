# 용어 및 처리 단위

pre-order 3차 개발에서 사용하는 공통 용어와 데이터·업무의 처리 단위를 정의한다. 세부 조건은 각 주제의 정책을 따른다. 앱 적용 범위는 Android다.

## 1. 캠페인과 상품

| 용어 | 정의·처리 단위 |
| --- | --- |
| 캠페인 | pre-order 운영 단위. Timeline·Product·Allocation·Hand Raiser 설정과 해당 주문을 관리한다. |
| Batch | 캠페인 안에서 주문·픽업 기간과 대상 근무지·구성원 등을 설정하는 단위. 하나의 캠페인에 여러 Batch가 있으며 기간이 겹칠 수 있다. |
| 프로덕트 그룹(Product Group) | Galaxy S26 Ultra와 같이 상품을 묶어 관리하는 단위. 캠페인당 최대 20개이며 그룹 안에 개별 SKU를 등록한다. |
| 상품 카테고리 | Smartphone 등 상품 속성과 입력 항목을 구분하는 기준. 프로덕트 그룹과 동일한 단위가 아니다. |
| SKU | 색상·용량 등으로 구분되는 개별 상품. 상품명(Product Name)과 SKU 코드는 구분하며, 주문 가능 근무지는 SKU별로 설정한다. |
| Product | 프로덕트 그룹·상품 정보와 SKU별 주문 가능 근무지를 설정하는 단계. 상품 파일은 그룹별로 처리한다. |
| Allocation | SKU의 수량을 유통사 단위로 관리하는 단계. 업로드 파일은 캠페인 전체 단위이며 그룹별 조회와 파일 적용 범위를 구분한다. |

- 캠페인의 진행 상태, Batch의 주문 가능 기간, Batch의 픽업 가능 기간은 서로 다른 판단 기준이다.
- 프로덕트 그룹 수 확대는 그룹 안의 SKU 수나 업로드 용량 확대를 의미하지 않는다.
- 세부 기준: [캠페인 및 Batch](Policy_03_캠페인_및_Batch.md), [Product 및 Allocation](Policy_04_Product_및_Allocation.md).

## 2. 유통사와 근무지

| 용어 | 정의·처리 단위 |
| --- | --- |
| 유통사 | Allocation 수량과 공유 재고를 관리하는 단위. SKU별 주문 가능 근무지를 지정해도 근무지별 재고로 분리하지 않는다. |
| 근무지 | 주문을 진행하는 매장. 주문에 연결된 근무지와 리더의 관리 구성원 범위는 별개다. |
| Batch 대상 근무지 | 해당 Batch에 참여할 수 있도록 설정된 근무지. 기존 사용자별 주문 참여 조건과 함께 적용한다. |
| 주문 가능 근무지 | 해당 SKU를 신규 주문할 수 있는 근무지 범위. ‘전체 근무지’ 또는 ‘특정 근무지’로 설정한다. |
| 전체 근무지 | 해당 캠페인의 모든 Batch 대상 근무지를 중복 없이 합친 범위. 회사의 모든 근무지를 의미하지 않는다. |
| 특정 근무지 | SKU에 저장한 선택 목록 중 현재 캠페인의 Batch 대상에도 포함되는 근무지. 저장된 선택과 현재 주문 가능한 범위는 구분한다. |

- Batch 대상에서 제외된 근무지의 SKU 선택 관계는 보존한다. 이후 다시 대상에 포함되면 보존된 선택이 유효해진다. 관리자가 직접 선택 해제한 관계는 복원하지 않는다.
- 세부 기준: [Product 및 Allocation](Policy_04_Product_및_Allocation.md).

## 3. 역할과 조회 범위

| 용어 | 정의·처리 단위 |
| --- | --- |
| 관리자 | 관리자 권한으로 pre-order를 운영하는 사용자. 주문 수정·삭제·이력 조회에서는 기존 관리자 계열(ADMIN·SUPER_ADMIN·OPERATOR) 기준을 따른다. |
| 별도 pre-order 조회 권한 리더 | 기존 pre-order 권한 설정으로 회사 내 전체 주문 조회가 허용된 리더. |
| 일반 리더 | 별도 pre-order 조회 권한이 없는 리더. 관리 그룹·하위 그룹 구성원의 주문을 정해진 범위에서 조회한다. |
| 관리 그룹·하위 그룹 | Shopl 조직의 구성원 관리 단위. 상품 묶음인 프로덕트 그룹과 구분하며, 리더 본인의 소속 그룹과도 동일하다고 간주하지 않는다. |
| 판매 담당 구성원 | 주문에 판매 담당자로 기록된 구성원. 일반 리더의 주문 조회 범위를 판정하는 기준이다. 같은 근무지의 모든 구성원을 의미하지 않는다. |
| 직원 모드·리더 모드 | 앱의 사용 모드. 계정 역할과 구분하며 모드별 기존 접근·작업 권한을 따른다. |

- 일반 리더의 담당 범위는 조회 시점의 관리 그룹과 구성원 소속을 기준으로 한다. 일괄 등록 주문 제외와 퇴사·삭제 구성원의 소속 판정은 권한 정책을 따른다.
- 주문 조회 범위, 고객 정보 표시 범위, 수정·삭제·이력 조회 권한은 각각 구분한다. 전체 주문 조회 권한이 모든 작업 권한이나 앱의 모든 개인정보 표시를 의미하지 않는다.
- 세부 기준: [권한 및 조회 범위](Policy_02_권한_및_조회_범위.md).

## 4. 주문 처리

| 용어 | 정의·처리 단위 |
| --- | --- |
| 임시 주문·진행 중 주문 | 주문을 시작했으나 최종 완료되지 않은 상태. 완료된 주문과 구분하며 기존 유효시간·재고 확보 조건을 따른다. |
| 주문 완료 | 신규 주문의 최종 저장이 완료된 상태. 픽업 완료를 의미하지 않는다. |
| 신규 등록 | 새 주문을 생성하는 작업. 앱 주문 진행과 대시보드 일괄 등록을 포함하며 기존 주문 수정과 구분한다. |
| 개별 수정 | 주문 상세에서 기존 주문 한 건의 정보를 변경하는 작업. |
| 일괄 수정 | 기존 주문 여러 건을 파일·편집 표로 변경하는 작업. 신규 주문을 생성하는 일괄 등록과 구분한다. |
| 픽업·수령 | 완료된 주문의 상품을 고객에게 인도하고 픽업 완료로 처리하는 작업. 화면의 ‘수령’과 정책의 ‘픽업’은 같은 업무를 가리킨다. |
| MBO | 기존 구매 조건에 따라 주문에 적용되는 혜택. 주문에 반영된 적용 여부·할인·금액과 판정에 사용한 기준 구매를 구분한다. |

- 주문 가능 근무지 제한은 신규 주문에 적용하며 기존 주문의 개별·일괄 수정에는 추가하지 않는다. 주문 근무지를 사용하지 않는 온라인 주문은 이 제한 검증에서 제외한다.
- 주문 완료 시 Batch 연결·MBO 확인과 픽업 시 기간·기기 식별정보 검증은 서로 다른 처리다.
- 세부 기준: [주문 및 픽업 처리](Policy_06_주문_및_픽업_처리.md).

## 5. Hand Raiser와 주문 이력

| 용어 | 정의·처리 단위 |
| --- | --- |
| Hand Raiser 명단 | 캠페인별로 등록한 이메일 목록. 명단 추가·삭제와 기존 주문 정보 변경은 별개다. |
| 주문별 Hand Raiser 여부 | 주문에 저장된 Yes/No 값. 명단이 바뀌어도 완료된 주문의 값을 자동 갱신하지 않는다. |
| 이메일 확인·재검증 | 캠페인 명단에서 현재 입력한 이메일을 확인하는 작업. 개별 주문 수정에 적용하며 일괄 수정의 Yes/No 직접 변경은 현행 유지한다. |
| 주문 이력 | 주문 생성·수정·픽업·삭제·복구·인보이스 재생성 작업의 기록. 현재 주문 정보와 별도로 기록 당시의 수행자·시각·표시값을 보존한다. |
| 인보이스 최초 발행 | 주문 완료에 따른 최초 PDF 생성. 별도 재생성 이력으로 기록하지 않는다. |
| 인보이스 재생성 | 최초 발행 이후 새 PDF를 생성하는 작업. 실제 생성 성공을 기록하며 단순 열람·다운로드와 구분한다. |

- 일괄 수정의 Hand Raiser 검증·인보이스 조건을 유지하더라도 실제 정보 변경과 PDF 재생성 성공의 주문 이력은 기록한다.
- 세부 기준: [Hand Raiser](Policy_05_Hand_raiser.md), [주문 이력](Policy_07_주문_이력.md).

## 6. 요약과 일별 추이

| 용어 | 정의·처리 단위 |
| --- | --- |
| 요약 | 적용된 조회 범위에서 Pre-order 수량·금액·픽업 수량을 집계한 값. 세 지표 모두 프로덕트 그룹·SKU별 상세 조회를 제공한다. |
| Pre-order 수량(Pre-order Unit) | 집계 대상 주문 수. 픽업 완료 주문도 포함하며 한 주문 행을 수량 1로 센다. |
| Pre-order 금액(Pre-order Amount) | 집계 대상 주문의 최종 주문 금액 합계. |
| 픽업 수량(Picked-up Unit) | 집계 대상 중 픽업 완료된 주문 수. |
| 일별 추이 | 날짜별 주문 수량 또는 픽업 수량. 주문은 주문 일시, 픽업은 픽업 일시를 기준으로 집계한다. 금액 추이는 제공하지 않는다. |
| 주간 합계 | 현재 표시하는 월요일~일요일 중 조회 가능한 날짜의 선택 지표 합계. 캠페인 전체 누적값과 구분한다. |

- 앱 요약·추이는 기존 오프라인 주문 집계 범위를 유지한다. 권한·필터·상품·기간 조건을 적용하며 임시·취소·삭제 주문은 제외한다.
- 요약에서 프로덕트 그룹 → SKU → 주문 목록으로 이동하는 흐름과 캠페인의 일별 추이 조회는 별도로 제공한다.
- 세부 기준: [요약 및 일별 추이](Policy_08_요약_및_일별_추이.md).
