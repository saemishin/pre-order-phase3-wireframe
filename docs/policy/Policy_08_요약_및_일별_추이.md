# 요약 및 일별 추이

## 1. 적용 범위와 조회 권한

- Android 앱 리더 모드의 캠페인 요약, 프로덕트 그룹·SKU별 수치, 일별 추이에 적용한다.
- [권한 및 조회 범위 정책](Policy_02_권한_및_조회_범위.md)을 공통 적용한다. 관리자·별도 pre-order 조회 권한 리더는 회사 내 기존 전체 범위, 일반 리더는 관리 그룹·하위 그룹 구성원의 허용된 주문 범위로 집계한다.
- 일반 리더의 현재 소속 판정, 퇴사·삭제 구성원, 일괄 등록 제외, 담당 범위 판정 불가 주문은 권한 정책을 따른다. 이 기준은 상위 합계·상품별 수치·차트에 동일하게 적용한다.
- 담당 범위 밖의 실적을 전체 합계나 비교값으로 별도 제공하지 않는다. 실제 주문 없음과 조회 가능한 주문 없음을 구분해 안내하지 않는다.
- 캠페인 노출 상태는 [캠페인 및 Batch 정책](Policy_03_캠페인_및_Batch.md)을 따른다. 집계 기준으로 캠페인 접근 권한이나 상태 범위를 확대하지 않는다.

## 2. 집계 대상과 지표

- 기존 앱 요약과 동일하게 **오프라인 주문**을 대상으로 한다. 온라인 주문을 새로 포함하지 않는다.
- 주문 완료·픽업 전(`BEFORE`)과 픽업 완료(`DONE`) 주문을 대상으로 한다. 진행 중 임시 주문(`ORDERING`), 취소(`CANCELLED`), 삭제된 주문은 제외한다.
- 한 주문 행을 수량 1로 센다. 픽업 완료된 주문도 주문 수량에 포함한다.

| 지표 | 집계 기준 | 요약 및 그룹·SKU별 수치 | 일별 추이 |
| --- | --- | --- | --- |
| Pre-order 수량 | 대상 주문 수 | 제공 | 제공 |
| Pre-order 금액 | 대상 주문의 최종 주문 금액 합계 | 제공 | 제공하지 않음 |
| 픽업 수량 | 대상 주문 중 픽업 완료 주문 수 | 제공 | 제공 |

- 요약의 실적 비율에서 주문 수량·금액의 분모인 배정 수량·금액은 기존 기준을 유지한다. 일반 리더의 담당 범위에 맞춰 배정값을 재분배하거나 축소하지 않는다.
- 픽업 실적 비율의 분모는 같은 조회 범위·검색 및 필터 조건의 오프라인 주문 수량이다. 분모가 0인 경우 등 기존 비율 처리를 유지한다.
- 그룹·SKU별 상세 수치는 세 지표 모두 제공한다. 추이를 추가해도 요약의 그룹 → SKU → 주문 목록 조회 흐름은 유지한다.
- SKU에서 주문 목록으로 진입할 때 선택 지표·SKU·권한·필터 조건을 이어 적용한다. 목록 안에서 진입 지표를 변경하지 않으며 검색·정렬도 같은 범위 안에서 적용한다. 주문 수량·금액은 같은 대상 주문, 픽업 수량은 대상 픽업 완료 주문을 조회한다.
- 선택 그룹의 합계와 SKU별 수치는 상위 요약에서 이어받은 같은 지표·권한·필터·기간 조건으로 집계한다. 그룹 합계는 그 조건에 해당하는 SKU별 수치의 합이며 추이의 주간 합계로 대체하지 않는다.
- SKU에서 조회할 주문이 0건이면 주문 목록에 진입하지 않는다. 주문 수량·금액은 대상 주문 유무, 픽업 수량은 대상 픽업 완료 주문 유무로 판단한다. 금액이 0이어도 대상 주문이 있으면 진입할 수 있다.

## 3. 날짜와 시간대

- 일별 주문 수량은 **주문 일시(`orderDt`)**, 일별 픽업 수량은 **픽업 일시(`pickUpDt`)**가 해당 날짜에 속하는 주문을 각각 집계한다.
- 픽업 추이에 주문 일시의 주간 조건까지 중복 적용하지 않는다. 이전 주에 주문하고 이번 주에 픽업한 주문은 이번 주 픽업 실적에 포함한다.
- 일별 날짜 구분·오늘·주간 경계는 기존 고객사 시간대를 따른다. 휴대폰 시간대나 임의의 고정 UTC 시차로 대체하지 않는다.
- 하루는 고객사 시간대의 해당 날짜 시작 이상, 다음 날짜 시작 미만으로 처리해 마지막 분·초의 데이터를 포함한다.
- 기존 요약의 기간 조건 및 집계 의미는 유지한다. 기존 기간별 픽업 수량은 주문 일시로 조회한 주문 중 현재 픽업 완료된 수량이며, 픽업 일시 기준의 일별 추이와 의미가 다를 수 있다.
- 요약의 캠페인 누적값과 추이의 주간 합계가 항상 같아야 하는 것은 아니다. 집계 대상·지표별 날짜 기준·기간·권한·필터가 모두 같을 때 정합성을 확인한다.

## 4. 상품 범위와 필터

- 기존 유통사·도·도시·근무지·SKU·Batch 필터를 요약과 추이에 공통 적용하며 SKU별 지표에도 같은 조건을 이어 적용한다. 필터 종류·후보 조회 방식은 기존 동작을 유지한다.
- 조회 범위는 **권한으로 허용된 주문 ∩ 기존 필터 조건 ∩ 현재 상품 선택**으로 제한한다. 상품 선택이나 필터 해제로 조회 권한을 확대하지 않는다.
- 그룹 단위 추이는 선택한 여러 프로덕트 그룹을 비교한다. SKU 단위 추이는 선택한 프로덕트 그룹 하나에 속하면서 기존 필터에 해당하는 SKU들을 비교한다.
- 별도의 범례 SKU 선택·해제 기능은 제공하지 않는다. 필요한 SKU로 범위를 좁히는 기능은 기존 상단 SKU 필터를 사용한다.
- Batch 필터는 선택한 Batch에 속한 주문만 집계하며, 캠페인 전체의 조회 가능 날짜 범위나 표시 주간을 바꾸지 않는다. Batch의 설정 기간과 차트 날짜의 교집합만 잘라내는 방식이 아니다.
- 예를 들어 같은 날짜에 Batch A 주문이 10건, Batch B 주문이 5건이면 A 선택 시 10건을 집계한다. 조회 가능한 날짜에 해당 Batch 실적이 없으면 0이다.
- 상품이 현재 필터 범위에 포함되면 실적이 0이어도 집계 항목에서 제거하지 않는다. 실적 유무만으로 상품 후보를 줄이지 않는다.

## 5. 조회 기간과 합계

- 해당 캠페인의 모든 Batch에 설정된 주문·픽업 기간을 포괄하는 범위를 전체 조회 기간으로 사용한다. 중간에 실적이 없는 날짜도 이 범위 안의 날짜로 취급한다.
- 실제 조회 가능한 실적 날짜의 상한은 오늘과 전체 조회 종료일 중 이른 날이다. 종료일이 없는 기간이 존재하더라도 미래 실적을 조회하는 의미로 확대하지 않는다.
- 조회 단위는 **월요일~일요일의 달력 주간**이다. 별도 주 시작요일 설정이나 사용자가 지정하는 임의 기간은 추가하지 않는다.
- 주간 합계는 현재 주간 중 조회 가능한 날짜에 대해 선택 지표·상품·권한·필터 조건으로 집계한 합계다. 전체 캠페인 누적값이 아니다.
- 날짜별 합계는 해당 날짜에 표시하는 상품들의 수량 합계다. 날짜별 합계들을 더한 값과 주간 합계가 일치해야 한다.

| 날짜·데이터 상태 | 처리 기준 |
| --- | --- |
| 조회 가능한 날짜에 실적 있음 | 해당 날짜의 실제 수량 집계 |
| 조회 가능한 날짜에 실적 없음 | 0으로 집계. 필터 결과 0건도 동일 |
| 전체 조회 기간 밖의 날짜·미래 날짜 | 집계 대상에서 제외. 0건 실적으로 취급하지 않음 |
| 모든 Batch의 주문·픽업 기간이 아직 시작 전 | 조회 가능한 날짜가 없는 상태로 처리 |

## 6. 데이터 변경과 갱신

- 기존처럼 캠페인 상세 진입·재진입 시 조회한다. 요약/추이 탭 전환 자체를 별도 갱신 조건으로 추가하지 않는다.
- 주간·지표·상품·필터가 바뀌면 해당 조건의 집계 결과를 제공한다. 이를 위해 필요한 조회는 진입 시 조회 기준과 별개로 처리한다.
- 수동 갱신·최근 업데이트 시각 표시·당겨서 새로고침·주기적 자동 갱신 기능은 추가하지 않는다. 기존 서버의 집계·캐시 주기를 새로 변경하는 정책도 아니다.
- 주문 수정·삭제 및 현재 소속 변경 등은 다음 조회 결과에 현재 데이터 기준으로 반영한다. 과거 날짜의 수치를 별도 스냅샷으로 고정하지 않는다.
- 조회 실패를 0건으로 변환하지 않는다. 현재 조건의 집계가 확인되지 않은 값을 정상 결과로 표시하지 않도록 기존 공통 조회·오류 처리를 적용한다.
