# Product 및 Allocation

## 1. 설정 단위와 데이터 보존

- 캠페인의 상품 설정은 프로덕트 그룹별로 관리한다. 캠페인당 그룹 수는 [캠페인 및 Batch 정책](Policy_03_캠페인_및_Batch.md)을 따른다.
- 다른 그룹을 조회·편집하더라도 각 그룹의 입력값·업로드한 상품·수량 설정을 유지한다.
- 현재 조회 중인지와 관계없이 모든 그룹을 캠페인 저장과 검증 대상에 포함한다.
- 신규 캠페인 생성과 기존 캠페인 수정에 동일한 기준을 적용하되, 기존 권한 및 상태별 수정 가능 범위는 유지한다.

## 2. 그룹 추가·이름

- 그룹을 추가해도 기존 그룹의 설정값은 유지한다.
- 이름 입력 전의 안내 표시는 실제 그룹명으로 저장하지 않는다.
- 이름 입력의 필수 여부·길이·중복 등 기존 유효성 검증은 유지한다. 여러 미입력 그룹에 같은 안내 표시를 사용하는 것은 실제 그룹명 중복을 허용한다는 의미가 아니다.

## 3. 그룹 삭제

- 그룹이 2개 이상일 때 삭제할 수 있으며, 마지막 1개 그룹은 삭제할 수 없다.
- 삭제를 확정한 그룹만 삭제 대상으로 처리한다. 삭제를 취소하면 기존 그룹 데이터를 유지한다.
- 그룹 삭제 시 연관 데이터 처리·실제 저장 시점·삭제 영향 범위는 기존 기준을 유지한다.

## 4. 검증과 수량 관리

- Product 및 Allocation 단계 완료 시 각 단계의 모든 그룹에 기존 유효성 검증을 적용한다. 일부 그룹에 검증 오류가 있으면 다음 단계로 진행할 수 없다.
- 그룹 탐색 구조 변경으로 상품 및 수량 설정의 기존 유효성 검증이나 저장 기준을 변경하지 않는다.
- Allocation의 수량은 기존과 같이 유통사 단위로 관리한다.
- Allocation 파일은 캠페인 전체 단위로 처리한다. 특정 그룹을 조회하더라도 파일의 적용 범위를 해당 그룹으로 제한하지 않는다. 템플릿·파일 검증·수량 적용·파일 삭제 및 초기화 기준은 기존 동작을 유지한다.

## 5. SKU별 주문 가능 근무지

- 주문 가능 근무지는 프로덕트 그룹이 아닌 개별 SKU 단위로 설정한다. 상품 카테고리와 관계없이 모든 SKU에 적용한다.
- 주문 가능 근무지는 필수 설정이며, 설정 방식은 ‘전체 근무지’와 ‘특정 근무지’로 구분한다. 신규 SKU와 기능 적용 전 생성된 캠페인의 기존 SKU는 ‘전체 근무지’를 기본값으로 적용한다.
- 기준이 되는 근무지 범위는 해당 캠페인의 모든 Batch 대상 근무지를 합친 목록이다. 여러 Batch에 포함된 근무지는 중복 제거한다. 회사의 모든 근무지를 의미하지 않는다.
- ‘전체 근무지’는 현재 Batch 대상 근무지 전체에서 주문할 수 있다. ‘특정 근무지’는 관리자가 선택한 근무지 중 현재 Batch 대상에 포함되는 근무지에서만 주문할 수 있다.
- 주문 가능 근무지 설정은 상품의 주문 자격을 제한한다. 재고 수량은 유통사 단위로 공유하며, 근무지별 수량을 별도로 할당하지 않는다.
- 설정은 Product 단계에서 SKU별로 제공한다. 업로드 파일에는 추가하지 않으며, 여러 SKU에 같은 설정을 복사하거나 일괄 적용하는 기능은 이번 범위에 포함하지 않는다.
- 캠페인 운영 중 설정 변경의 권한·시점은 기존 캠페인 수정 정책을 따른다.

## 6. Batch 변경과 선택 보존

| 설정·변경 | 적용 기준 |
| --- | --- |
| 전체 근무지 | 현재 모든 Batch 대상 근무지의 합집합을 사용한다. Batch 대상에 추가·제외된 근무지는 주문 가능 범위에도 즉시 반영한다. |
| 특정 근무지 | 저장된 선택 목록과 현재 모든 Batch 대상 근무지의 합집합이 겹치는 근무지만 실제 주문 가능 범위로 사용한다. |
| 선택한 근무지가 Batch 대상에서 제외됨 | 실제 주문 가능 범위에서 제외하되, SKU에 저장된 선택은 보존한다. |
| 제외됐던 근무지가 Batch 대상에 다시 포함됨 | 보존된 선택이 다시 유효해져 주문 가능 범위에도 포함된다. 처음부터 선택하지 않은 근무지는 자동 포함하지 않는다. |
| 관리자가 SKU에서 근무지를 직접 선택 해제함 | 저장된 선택에서 제거한다. 이후 Batch에 다시 포함되더라도 선택이 복원되지 않는다. |
| 실제 주문 가능 근무지가 0개임 | 0개 상태를 허용하며 ‘전체 근무지’로 자동 전환하지 않는다. 해당 SKU는 신규 주문 시 어떤 근무지의 상품 목록에도 표시되지 않는다. |

- 필수 설정이라는 이유로 특정 근무지 0개 상태의 저장을 차단하지 않는다.
- Batch 후보 목록의 변경이나 설정 화면 조회만으로 저장된 선택 목록을 현재 후보와의 교집합으로 덮어쓰지 않는다.

## 7. 상품 업로드·초기화

- 파일 업로드로 새로 생성되는 SKU의 주문 가능 근무지는 ‘전체 근무지’로 설정한다. 필요한 SKU만 화면에서 변경한다.
- 상품 초기화 후 파일을 다시 업로드하면 기존 SKU의 주문 가능 근무지 설정을 보존하지 않는다. 새로 생성한 SKU는 ‘전체 근무지’로 설정하며, 특정 근무지 제한이 필요하면 다시 설정한다.
- 상품 업로드와 캠페인 생성·수정의 기존 저장 흐름은 유지한다.

## 8. 주문에 적용하는 기준

| 주문 처리 | 적용 기준 |
| --- | --- |
| Android 앱 신규 주문의 상품 조회 | 주문을 진행하는 근무지에서 주문 가능한 SKU만 표시한다. 기존 Batch 참여·근무지 선택 조건도 유지한다. |
| Android 앱 주문 진행 중 | [다음]과 [완료] 시 주문 근무지와 선택 SKU의 주문 가능 여부를 다시 검증한다. 진행 중 설정이 변경되어 주문 불가 상태가 되면 다음 단계 진행 또는 완료를 차단한다. 차단 시 진행 중인 주문의 입력값을 삭제하지 않는다. |
| 대시보드 신규 주문 등록 | 주문 근무지와 SKU의 주문 가능 여부를 검증한다. |
| 대시보드 일괄 주문 등록 | 각 주문의 근무지와 SKU를 검증하며, 오류 행은 기존 일괄 등록 오류 표시 방식으로 안내한다. |
| 온라인 주문 | 주문 근무지를 사용하지 않는 온라인 주문은 주문 가능 근무지 제한 검증에서 제외한다. 기존 온라인 주문의 다른 검증은 유지한다. |
| 이미 완료된 주문 | 이후 설정 변경의 영향을 받지 않는다. 기존 주문의 근무지·SKU를 변경하거나 주문을 취소하지 않으며, 조회·픽업도 이 설정을 이유로 제한하지 않는다. |
| 관리자 기존 주문 수정 | 개별·일괄 수정에서 SKU를 변경하더라도 주문 가능 근무지 검증은 추가하지 않는다. 재고 등 기존 주문 수정 검증은 유지한다. |

- 대시보드 신규 일괄 등록에서는 파일 적용 시 각 행을 검증하고, 상품 또는 주문 근무지가 변경되면 변경된 조합을 다시 검증한다. 최종 저장 시에도 현재 저장된 설정으로 검증하며 주문 불가 조합을 등록하지 않는다. 기존 파일·필수값·재고 등 다른 검증은 유지한다.
- 대시보드 일괄 등록의 오류 표시·값 수정·저장 버튼 동작은 [일괄 주문 등록 화면](../description/Web_dc_11_일괄_주문_등록.md)을 따른다.
- 주문 가능 여부는 상품 선택 시점의 값으로 고정하지 않는다. 각 검증 시점의 저장된 설정을 기준으로 판정하며, 앞선 단계에서 통과했더라도 완료 시 검증을 생략하지 않는다.
- 저장된 설정 변경은 이후 신규 주문과 아직 완료되지 않은 주문에 즉시 적용한다. 설정 팝업의 [적용]은 캠페인 편집값 반영이며, 서버 저장은 기존 캠페인 저장 흐름을 따른다.
