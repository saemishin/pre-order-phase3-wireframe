# Hand Raiser

## 1. 명단 관리 단위와 적용 범위

- Hand Raiser 명단은 캠페인별 이메일 목록으로 관리한다. 캠페인 생성·수정과 생성 후 명단 관리에 같은 이메일 판정 기준을 적용한다.
- 명단 업로드는 캠페인 저장의 필수 조건이 아니다. 명단이 없거나 업로드 성공 건이 0건이어도 캠페인 생성·수정 자체는 저장할 수 있다.
- 명단 추가·삭제는 기존 캠페인 관리 권한 범위에서 제공한다. 주문 조회 권한 확대만으로 명단 변경 권한을 부여하지 않는다.
- 대용량 명단 전체를 화면에 나열하거나 개별 입력 행으로 편집하지 않는다. 등록은 파일로 처리하고, 등록 여부는 이메일 검색으로 확인한다.
- 캠페인 생성·수정 및 추가 업로드의 파일 입력 형식과 결과 판정 기준은 공통으로 사용한다. 캠페인 생성 후 업로드는 기존 명단에 추가하며 전체 명단을 교체하지 않는다.

## 2. 파일 업로드와 결과 판정

- Excel·CSV 파일을 지원하며 대용량 업로드에는 CSV를 권장한다.
- 한 번에 많은 이메일이 포함된 운영 파일과 누적 명단을 처리할 수 있도록 개선한다. 파일을 잘게 분할해 올리는 것을 기본 운영 방식으로 요구하지 않는다. 파일 크기·건수·처리 시간의 구체 상한은 개발 검토로 정하며 임의 숫자를 확정하지 않는다.
- 기존 이메일 유효성 및 파일 내부 중복 처리 기준을 우선 재사용한다. 정상 검증이 끝난 파일은 성공·실패 건수를 제공하고 성공한 이메일만 등록한다.
- 실패 행이 있다는 이유로 성공 행의 등록을 차단하지 않는다. 파일 전송·파싱 등 시스템 실패는 정상적인 성공 0건과 구분한다.
- 이미 명단에 등록된 이메일은 성공으로 집계하고 실패 파일에서 제외한다. 해당 이메일은 다시 등록하지 않으므로 성공 건수에는 명단에 새로 추가되지 않은 이메일도 포함된다.
- 명단 추가 업로드와 검색에서 이메일의 기존 등록 여부는 주문의 Hand Raiser 판정 기준을 따른다.

## 3. 등록 반영과 실패 파일

| 처리 | 적용 기준 |
| --- | --- |
| 캠페인 생성·수정 | 파일 처리 결과의 성공 건을 캠페인 저장 시 반영한다. 업로드하지 않았거나 성공 0건이어도 캠페인 자체 저장은 허용한다. 기존 명단이 있는 캠페인은 추가분을 반영하며 기존 명단을 지우지 않는다. |
| 캠페인 상세의 추가 업로드 | 파일 처리 완료 후 성공 1건 이상일 때 추가분 저장을 허용한다. 성공 0건이면 추가 저장을 허용하지 않는다. |
| 저장 전 파일 제거·취소 | 현재 업로드의 미반영 결과를 폐기한다. 이미 저장된 명단을 삭제하지 않는다. |
| 일부 실패 | 성공 건만 반영한다. 실패 건은 필요 시 파일을 수정해 다시 업로드하며, 수정·재업로드는 필수가 아니다. |

- 실패 이메일은 업로드 양식과 같은 형식의 파일로 제공하여 수정 후 재업로드할 수 있게 한다. 실패 사유·행 번호 등의 별도 컬럼을 임의로 추가하지 않는다.
- 실패 파일은 해당 파일 업로드 단계에서만 내려받을 수 있다. 캠페인 생성·수정 또는 추가 업로드 저장 완료 후 별도 실패 파일 다운로드 이력은 제공하지 않는다.
- 같은 양식이라는 기준이 확장자·인코딩까지 같아야 한다는 뜻은 아니다. 지원 형식과 재업로드 호환성은 개발에서 확인한다.
- 생성 중 여러 파일을 동시에 첨부하거나 파일별 결과를 누적 표시하는 기능은 이번 범위에 포함하지 않는다.

## 4. 이메일 검색과 삭제

- 현재 캠페인의 명단에서 이메일 전체 주소가 정확히 일치하는 항목을 검색한다. 부분 일치 검색과 전체 목록 조회는 제공하지 않는다.
- 검색한 이메일 여러 건을 선택해 한 번에 삭제할 수 있다. 검색 조건이 달라져도 선택한 대상은 유지한다.
- 이미 주문에 사용된 이메일도 명단에서 삭제할 수 있다. 삭제 대상은 캠페인 명단의 이메일이며 기존 주문·혜택 사용 이력은 삭제하지 않는다.
- 명단 정정은 검색·삭제 후 올바른 이메일을 파일로 추가하는 방식으로 처리한다. 이메일 문자열을 직접 수정하는 별도 기능은 제공하지 않는다.

## 5. 주문 판정과의 관계

- 신규 주문 완료 시 현재 캠페인 명단에서 이메일을 다시 조회하고 최종 Hand Raiser 여부를 저장하는 기존 동작을 유지한다. 입력 단계에서 확인한 Yes/No를 고정해 저장하지 않는다.
- 진행 중 명단 변경으로 최종 판정이 달라질 수 있으나, 명단 제외만으로 주문 전체를 차단하는 새 검증을 추가하지 않는다.
- 명단 추가·삭제로 이미 완료된 주문의 Hand Raiser 여부를 자동 갱신하지 않는다.
- 기존 주문의 여부 변경은 아래 주문 수정 기준을 따른다. 명단 변경 자체와 주문 정보 수정을 구분한다.

## 6. 기존 주문의 Hand Raiser 여부 수정

- 이 절의 확인·초기화·재검증은 주문 상세의 개별 수정에 적용한다. 일괄 수정은 8절의 현행 유지 기준을 따른다.

- 대시보드의 기존 주문 수정 권한·수정 가능 조건을 유지한다. 조회 권한만 있는 리더에게 주문 수정 권한을 추가하지 않는다.
- Hand Raiser 여부는 주문이 속한 캠페인의 명단에서 이메일을 확인한 결과로 변경한다. 사용자가 Yes/No를 임의로 지정하지 않는다.
- 수정 시작 시 주문에 저장된 기존 여부를 유지한다. 수정 화면 진입만으로 현재 명단을 조회하거나 기존 여부를 변경하지 않는다.
- 확인 결과를 초기화하거나 이메일을 변경하면 재검증이 필요하다. 재검증 전에는 해당 주문의 수정 내용을 저장할 수 없다.
- 재검증에는 수정 화면에 입력된 현재 이메일을 사용한다. 이메일과 여부를 함께 수정할 때도 저장 전의 기존 이메일로 검사하지 않는다.
- 명단에 있으면 Yes, 없으면 No로 판정한다. No도 정상적으로 확인된 결과이며, 다른 기존 저장 조건을 충족하면 저장할 수 있다. 명단 재확인으로 No → Yes와 Yes → No 모두 변경할 수 있다.
- 이메일과 확인 상태를 변경하지 않고 다른 정보만 수정하면 기존 여부를 유지한다. 기존 Yes 주문이라는 이유만으로 매번 명단 재검증을 요구하지 않는다.
- 초기화·재검증은 저장 전 수정 상태에만 반영한다. 수정 저장에 성공할 때 주문에 반영하고, 수정 취소 시 기존 주문 값을 유지한다.
- 명단 조회 실패는 명단에 없는 No 판정과 구분한다. 정상 판정을 받지 못한 상태에서는 재검증이 완료된 것으로 처리하지 않는다.

## 7. 주문 수정과 인보이스·이력 연계

- 개별 주문 수정 저장 후 Hand Raiser 여부가 실제 변경된 경우를 인보이스 재생성 조건에 추가한다. 기존의 다른 인보이스 재생성 조건은 유지한다.
- 실제 변경된 Hand Raiser 여부는 [주문 이력 정책](Policy_07_주문_이력.md)에 따라 변경 전후 값과 수정자·수정일시를 기록한다. 이메일도 변경됐다면 이메일 수정 이력을 별도로 남긴다.
- 재검증 결과가 기존 여부와 같으면 Hand Raiser 수정 이력을 만들지 않고, Hand Raiser 변경에 따른 인보이스 재생성 조건도 발생하지 않는다. 함께 수정한 이메일 등 다른 항목의 기존 처리까지 제외하는 것은 아니다.
- 인보이스는 최초 발행 이후 새 PDF 생성에 성공하면 정보 수정 이력과 별도로 재생성 이력을 남긴다. 정보 수정에 따른 자동 재생성의 수행자는 수정을 실행한 사용자로 기록한다. 최초 발행·실패 시도 등 나머지 기록 기준은 주문 이력 정책을 따른다.

## 8. 일괄 수정의 적용 범위

- 일괄 주문 수정은 이메일 입력·Hand Raiser Yes/No 직접 선택·검증·저장·인보이스 처리를 현행 유지한다. P07의 개별 수정 기능을 일괄 수정에 확대하지 않는다.
- 이메일을 변경해도 기존 Hand Raiser 여부를 초기화하거나 명단에서 자동 재판정하지 않는다. 이메일과 Yes/No를 함께 변경하는 경우에도 입력한 값을 기존 방식으로 반영한다.
- No → Yes와 Yes → No 변경에 명단 포함 여부 검증을 추가하지 않는다. 이메일 필수값·형식 등 기존 검증과 오류 안내·저장 처리는 유지한다.
- 일괄 수정의 인보이스 재생성 조건을 변경하지 않는다. Hand Raiser 여부만 변경된 경우를 새 재생성 조건으로 추가하지 않으며, 이메일 등 기존 재생성 대상 항목이 함께 변경되면 기존 조건을 따른다.
- P01의 주문 이력 기록은 별도로 적용한다. 일괄 수정에서 실제 저장된 이메일·Hand Raiser 여부가 바뀌면 변경 이력을 남기고, 기존 조건으로 인보이스가 재생성되어 새 PDF 생성에 성공하면 재생성 이력을 남긴다. 인보이스의 재생성 조건 유지와 이력 기록 제외를 혼동하지 않는다.
- 일괄 수정의 신규 검증·화면 변경·인보이스 조건 보완은 이번 P07 개발 범위에서 제외한다. 별도 와이어프레임·화면 디스크립션을 추가하지 않으며, 고객 공유용 P07 범위에도 포함하지 않는다.
