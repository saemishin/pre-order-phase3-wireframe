# pre-order 3차 개발

2027년 2월 pre-order 캠페인을 위한 개발 범위와 관련 기획 문서의 인덱스다.

## 문서 구성

- 개발 아이템 ID는 범위와 변경 경과를 추적하는 데 사용한다. 정책·화면 문서의 번호와는 별개다.
- `policy/`에는 주제별 정책을 작성한다. 여러 화면에서 공통으로 적용되는 규칙의 기준이다.
- `description/`에는 화면별 동작을 작성한다. 한 화면에 여러 개발 아이템이 포함되면 한 문서에서 함께 설명하고 관련 정책을 참조한다.
- 같은 화면의 내용은 P01·P04·P06 등 개발 아이템이 달라도 기존 디스크립션에 통합한다. 탭·조회/수정 모드·역할·데이터 상태는 화면 내부 요소와 케이스로 구분하며, 기능이 추가됐다는 이유로 별도 파일을 만들지 않는다.
- 별도로 진입하는 페이지·단계·독립 팝업은 화면 단위로 구분할 수 있다. 파일명은 특정 개발 아이템보다 화면 이름을 기준으로 하며, 개발 아이템과의 연결은 화면 목차·개발 범위에서 관리한다.
- 통합할 때 기존 명세·문구·조건·예외·미확정 사항을 보존하고 번호·앵커·참조 링크를 함께 정리한다. 후속 화면 검토 전인 내용을 확정 명세처럼 채워 넣지 않는다.
- 앱 명세는 Android에 적용한다.

## 작성 기준

- `shopl-pm`의 `tools/rules_description.md`를 따른다.
- 디스크립션은 진입 경로 뒤 구분선, 컴포넌트별 번호 헤딩, 조건 분기별 `케이스 / 조건 / 명세` 표로 작성한다.
- 디스크립션 번호는 처리 순서가 아니라 화면 요소의 구조를 따른다. 팝업·카드·탭 등 상위 요소 아래 검색창·목록·필드·버튼을 하위 번호로 구분한다. 검증·저장·성공 및 실패·갱신·토스트는 해당 동작을 발생시키거나 결과를 표시하는 요소 안에 작성한다.
- 구조를 바꿀 때 기존 노출 조건·활성화 조건·표시 문구·예외·개발 확인 사항을 보존하고, 케이스 번호와 문서 내 참조를 함께 갱신한다.
- 정책과 디스크립션은 상대 경로로 연결한다. 화면에 적용되는 동작은 설명하되 공통 정책 전체를 반복 복제하지 않는다.
- 정책에는 적용 단위·상한·권한·검증 조건·데이터 기록 및 보존 기준을 둔다. 탭·버튼·카드·정렬·선택 이동·스크롤·표시 문구는 화면 디스크립션에서 관리한다. 권한에 따른 조회 제한이나 기록 데이터의 범위는 화면에 영향을 주더라도 정책으로 유지한다.
- 이미 결정한 상위 정책과 추가로 확인할 세부 동작을 구분한다. 참고 기능의 정책을 pre-order에 자동 적용하지 않는다.
- 디스크립션에는 확정된 화면 동작을 작성한다. 개발 확인 사항은 별도 문서에 모으고, 의사결정 경과는 기획 기록에서 관리한다.
