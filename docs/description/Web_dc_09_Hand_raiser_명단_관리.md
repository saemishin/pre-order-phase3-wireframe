# Hand Raiser 명단 관리

진입 경로: 대시보드 > pre-order > 캠페인 상세 > Hand Raiser > 검색 또는 추가 [+] 아이콘

---

- 명단의 정확 일치 검색·선택 삭제·추가 업로드는 [Hand Raiser 정책](../policy/Policy_05_Hand_raiser.md)을 따른다.
- 팝업을 닫거나 취소해도 이미 완료한 삭제·저장을 되돌리지 않는다. 아직 실행하지 않은 선택과 업로드 결과만 폐기한다.

## 1. **이메일 관리 팝업**

- 검색 입력과 선택을 포함하므로 팝업 바깥 클릭으로 닫지 않는다. 헤더 X를 추가하지 않는다.

### 1-1. **헤더**

| 구분 | 정의 |
| --- | --- |
| Header | 타이틀은 ‘이메일 관리’이며 헤더 닫기 [×]는 제공하지 않는다. |

### 1-2. **이메일 검색창**

- Shoplflow SearchBar를 사용하며 플레이스홀더는 ‘검색’이다. 별도 검색 버튼은 제공하지 않는다.
- 검색창 안 돋보기 또는 Enter로 현재 캠페인 명단에서 이메일 전체 주소를 정확 일치 검색한다. 타이핑만으로 부분 검색하지 않는다.

### 1-3. **이메일 목록·체크박스**

| 구분 | 정의 |
| --- | --- |
| Body | 검색창 아래 한 목록에 체크한 이메일과 현재 검색 결과를 함께 표시한다. 별도 선택 목록 패널은 제공하지 않는다. |

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 1-3-1 | 검색 전·선택한 이메일 없음 | <ul><li>빈 목록 영역에 ‘등록된 Handraiser 명단에서 이메일 주소를 검색합니다.’ 안내를 표시한다.</li></ul> |
| Case 1-3-2 | 정확 일치 결과 있음 | <ul><li>이메일과 체크박스를 한 행으로 표시한다.</li><li>이미 선택해 둔 이메일과 같은 결과이면 중복 행을 만들지 않고 체크 상태로 표시한다.</li></ul> |
| Case 1-3-3 | 검색 결과 없음 | <ul><li>‘결과가 없습니다.’를 표시한다.</li><li>앞서 체크한 이메일은 유지한다. 이 문구는 현재 검색 결과가 없다는 의미다.</li></ul> |
| Case 1-3-4 | 검색어를 모두 지움 | <ul><li>현재 검색 결과를 즉시 초기화하고 체크한 이메일만 남긴다.</li><li>직접 지우기와 검색창 지우기 아이콘에 같은 기준을 적용한다.</li><li>선택 항목이 있으면 검색 전 안내를 표시하지 않고, 없으면 Case 1-3-1 상태로 돌아간다.</li></ul> |

- 검색 요청 실패를 ‘결과가 없습니다.’로 처리하지 않는다.

- 체크한 이메일은 검색어·검색 결과와 관계없이 같은 목록에 유지한다. 새 검색 시 미선택 이전 결과는 교체한다.
- 유지한 선택 목록 뒤에 새 검색 결과를 표시한다. 같은 이메일은 한 번만 표시한다.
- 체크 해제한 항목이 현재 검색 결과이면 미선택 상태로 남기고, 이전 검색에서 유지하던 항목이면 목록에서 제거한다.
- 검색어나 체크 상태 변경만으로 명단을 삭제하지 않는다. [삭제]와 확인창의 [삭제]를 거쳐 실행한다.

### 1-4. **푸터의 닫기·삭제 버튼**

| 구분 | 정의 |
| --- | --- |
| Footer | <ul><li>[닫기] 버튼 : 검색어·미실행 선택을 폐기하고 팝업을 닫는다. 삭제를 실행하지 않는다.</li><li>[삭제] 버튼 : 선택 1건 이상일 때 활성화하며 삭제 확인창을 연다.</li></ul> |

## 2. **삭제 확인창**

- 이메일 관리의 [삭제] 선택 시 앞 이메일 관리 팝업을 유지하고 확인창을 연다. 바깥 클릭으로 닫지 않는다.

### 2-1. **헤더**

| 구분 | 정의 |
| --- | --- |
| Header | ‘삭제하시겠습니까?’를 표시하고 헤더 닫기 [×]는 제공하지 않는다. |

### 2-2. **안내 문구**

| 구분 | 정의 |
| --- | --- |
| Body | 선택한 이메일을 명단에서 삭제합니다. 이미 완료된 주문의 Hand Raiser 여부는 변경되지 않습니다. |

### 2-3. **푸터의 취소·삭제 버튼**

| 구분 | 정의 |
| --- | --- |
| Footer | <ul><li>[취소] 버튼 : 확인창만 닫고 앞 팝업의 검색어·선택을 유지한다.</li><li>[삭제] 버튼 : 선택한 이메일을 현재 캠페인 명단에서 삭제한다.</li></ul> |

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 2-3-1 | 전체 삭제 성공 | <ul><li>확인창만 닫고 이메일 관리 팝업을 유지한다.</li><li>삭제한 이메일을 검색 결과·선택 목록에서 제거하고 선택 상태를 초기화한다. 나머지 현재 검색 결과는 유지한다.</li><li>캠페인 상세의 명단 총개수를 갱신한다.</li><li>성공 Toast 노출 (삭제되었습니다. / cm_deleted).</li></ul> |
| Case 2-3-2 | 선택한 이메일 중 일부 또는 전부 삭제 실패 | <ul><li>이메일 관리 팝업에서 삭제에 실패한 이메일은 선택 상태로 유지해 다시 삭제할 수 있게 한다. 전체 실패 시 기존 선택을 모두 유지한다.</li><li>일부만 삭제된 경우 삭제된 이메일만 검색 결과·선택 목록에서 제거하고 상세의 총개수를 실제 명단에 맞춰 갱신한다.</li><li>전체 삭제 성공 토스트는 표시하지 않는다.</li></ul> |

## 3. **추가 업로드 팝업**

- 바깥 클릭으로 팝업을 닫지 않는다.

### 3-1. **헤더**

| 구분 | 정의 |
| --- | --- |
| Header | 타이틀은 ‘추가 업로드’이며 헤더 닫기 [×]는 제공하지 않는다. |

### 3-2. **안내 박스·공통 파일 업로드 영역**

| 구분 | 정의 |
| --- | --- |
| Body | <ul><li>‘기존 업로드된 명단에 이메일을 추가로 업로드합니다.’ 안내를 박스로 표시한다.</li><li>캠페인 생성·수정과 동일한 공통 파일 업로드 영역을 제공한다.</li></ul> |

- 양식 다운로드·Excel/CSV 업로드·파일 정보·파일 제거·처리 중 스켈레톤·성공/실패 건수·실패 파일은 [공통 파일 업로드 영역](Web_dc_07_캠페인_Hand_raiser.md#2-1-공통-파일-업로드-영역) 및 해당 문서의 [성공·실패 결과 영역](Web_dc_07_캠페인_Hand_raiser.md#2-2-성공실패-결과-영역)을 그대로 적용한다.
- 업로드 결과에서 실패 1건 이상일 때만 실패 파일 다운로드와 ‘성공한 이메일만 등록됩니다.’ 안내를 제공한다.

### 3-3. **푸터의 취소·저장 버튼**

| 구분 | 정의 |
| --- | --- |
| Footer | <ul><li>[취소] 버튼 : 미저장 업로드 결과를 폐기하고 팝업을 닫는다. 기존 명단은 유지한다.</li><li>[저장] 버튼 : 정상 파일 처리 완료 후 성공 1건 이상일 때 활성화한다.</li></ul> |

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 3-3-1 | 업로드 전·파일 처리 중·성공 0건 | <ul><li>[저장] 버튼을 비활성화한다.</li><li>정상 처리된 성공 0건이면 실패 파일 다운로드·파일 제거 후 재업로드·취소는 가능하다.</li><li>처리 중에는 파일 제거를 비활성화한다.</li></ul> |
| Case 3-3-2 | 처리 완료·성공 1건 이상에서 [저장] | <ul><li>성공한 이메일 중 아직 명단에 없는 주소만 추가한다.</li><li>저장 성공 후 팝업을 닫고 상세의 명단 총개수를 갱신한다.</li><li>성공 Toast 노출 (저장되었습니다. / cm_saved).</li><li>실패 파일은 저장 완료 후 다시 제공하지 않는다.</li></ul> |
| Case 3-3-3 | 저장 실패 또는 저장 응답 미수신 | <ul><li>공통 오류 문구를 토스트로 표시한다.</li><li>추가 업로드 팝업과 파일 처리 결과를 유지한다. 사용자는 파일을 다시 올리지 않고 같은 팝업에서 [저장]을 다시 누를 수 있다.</li><li>같은 업로드는 한 번만 반영한다. 첫 요청에서 이미 저장됐다면 재시도로 이메일이 중복 등록되거나 명단 총개수·최근 업데이트 시각이 다시 바뀌지 않는다.</li></ul> |

- 파일 처리 성공만으로 저장 성공 토스트를 표시하지 않는다. 성공 0건과 취소에도 표시하지 않는다.
- 토스트 노출 시간은 기존 공통 기준을 따른다.
