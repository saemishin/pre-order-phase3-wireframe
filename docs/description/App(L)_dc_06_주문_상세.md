# 앱 주문 상세 · 리더 모드

진입 경로: Android 앱 > 리더 모드 > Pre-order > 캠페인 상세 > 주문 목록 > 주문 선택

---

- 고객 개인정보 비노출(P04)과 역할별 주문 조회 범위(P04-A)를 같은 주문 상세 화면에 적용한다. 기존 주문 정보·고객 정보 탭과 항목 구성을 유지한다.
- [권한 및 조회 범위 정책](../policy/Policy_02_권한_및_조회_범위.md)을 따른다. 직원 모드의 정보 표시 기준은 이번 변경 대상이 아니다.

## 1. **상단 내비게이션**

- 제목 없이 기존 뒤로 버튼을 제공한다.
- 뒤로 선택 시 진입했던 주문 목록으로 돌아간다. 목록의 조회 권한·SKU·진입 지표·필터 조건과 검색어·정렬·스크롤 위치를 유지한다.
- 웹 주문 상세의 더보기 메뉴나 수정·삭제·주문 이력 메뉴를 앱에 추가하지 않는다.

## 2. **주문 정보·고객 정보 탭**

### 2-1. **탭 선택**

- 기존 순서인 `주문 정보`, `고객 정보`를 유지한다. 최초 진입 시 주문 정보 탭을 선택한다.
- 선택한 탭의 정보 영역을 표시한다. 두 리더에게 개인정보 3개를 숨기더라도 고객 정보 탭 자체는 유지한다.
- 탭 전환으로 조회 대상 주문이나 사용자 권한을 변경하지 않는다.

### 2-2. **탭 공통 조회 대상**

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 2-2-1 | 관리자 | <ul><li>기존 회사 내 전체 조회 범위에서 선택한 주문을 조회한다.</li></ul> |
| Case 2-2-2 | 별도 pre-order 조회 권한 리더 | <ul><li>기존 회사 내 전체 조회 범위에서 선택한 주문을 조회한다.</li><li>고객 개인정보 표시 기준은 관리자와 구분한다.</li></ul> |
| Case 2-2-3 | 일반 리더 | <ul><li>관리 그룹·하위 그룹 구성원의 조회 가능한 주문만 조회한다.</li><li>현재 소속, 퇴사·삭제 구성원, 일괄 등록 주문 제외 등의 판정은 권한 정책을 따른다.</li></ul> |

- 목록에서 선택한 주문과 상세의 주문이 일치해야 한다. 탭·첨부·프로필 등의 진입을 이유로 주문 조회 범위를 확대하지 않는다.

## 3. **주문 정보 탭 · 플랫폼·상품 영역**

### 3-1. **플랫폼 표시**

- 기존 주문 플랫폼 표시를 유지한다.

### 3-2. **상품 이미지·제품명·SKU·금액**

- 상품 이미지, 제품명, SKU 코드, 상품 금액 순서의 기존 구성을 유지한다.
- 제품명은 기존처럼 최대 두 줄로 표시하고 초과하면 말줄임 처리한다.
- 상품 이미지 선택 시 기존 이미지 확대 동작을 유지한다.
- 금액과 MBO 적용 시 표시 방식은 기존 주문 상세 기준을 유지한다. 진입 지표가 수량·금액·픽업 중 무엇인지에 따라 상품 정보를 바꾸지 않는다.

## 4. **주문 정보 탭 · 주문 정보 영역**

### 4-1. **주문 코드·Batch**

- 주문 코드와 연결된 Batch를 기존 순서로 표시한다.
- Batch 선택 시 해당 Batch의 주문 기간·픽업 기간을 펼치고, 다시 선택하면 접는다. 기존 날짜·요일·시간 표기 기준을 유지한다.
- Batch를 펼치는 동작은 정보 조회이며 연결된 Batch를 수정하지 않는다.

### 4-2. **유통사·주문 일시·주문 매장·담당 직원**

- 유통사, 주문 일시, 주문 매장, 담당 직원 순서로 기존 정보를 표시한다.
- 플랫폼에 따른 매장 주소·담당 직원의 표시 조건과 값이 없을 때의 기존 표기를 유지한다.
- 담당 직원 프로필 선택은 기존 공통 프로필 조회 권한과 동작을 따른다. 일반 리더의 주문 조회 허용만으로 구성원 정보 조회 권한을 추가하지 않는다.

### 4-3. **주문 영수증·연결 버튼**

- 기존 `주문 영수증` 영역과 `영수증 보기`, `재발송` 버튼의 플랫폼별 제공 조건·동작을 유지한다.
- 고객 정보 탭에서 이메일을 숨기는 것과 영수증·재발송 기능의 제공 조건은 구분한다. 이번 개인정보 비노출만으로 관련 버튼을 일괄 제거하거나 새로 추가하지 않는다.
- 버튼 선택 후의 기존 파일 열람·발송 처리와 안내를 유지한다.

### 4-4. **MBO·결제 및 추가 정보**

- `MBO Status`, `Multibuy Phone`과 사용 중인 결제 속성의 기존 순서·표시 조건을 유지한다.
- 속성 유형에 따라 단일값·복수값·텍스트·첨부파일을 기존 방식으로 표시한다. 파일 선택 시 기존 열람 동작을 유지한다.

## 5. **주문 정보 탭 · 수령 정보 영역**

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 5-1 | 픽업 전 | <ul><li>기존 상태 표시와 `아직 수령이 진행되지 않았습니다.` 안내를 제공한다.</li><li>수령 매장과 플랫폼에 따른 주소 표시를 유지한다.</li><li>픽업 버튼은 해당 주문의 픽업 기간·플랫폼 등 기존 제공 조건을 따른다.</li></ul> |
| Case 5-2 | 픽업 완료 | <ul><li>픽업 완료 상태, 수령 매장, 수령 일시, 담당 직원과 등록된 픽업 속성을 기존 순서로 표시한다.</li><li>IMEI 등의 항목은 기존 설정·등록값에 따라 표시한다.</li></ul> |

- 상세 조회가 가능하다는 이유로 기존에 허용되지 않은 픽업 작업을 새로 허용하지 않는다. 버튼 선택 후의 주문별 기간 확인과 픽업 진행 처리는 기존 기준을 따른다.
- 이번 화면의 역할별 조회·개인정보 표시와 픽업 진행 단계의 검증 개선은 구분한다.

## 6. **고객 정보 탭**

### 6-1. **이름·휴대폰 번호·이메일·신분증 번호**

- 기존 기본 정보의 순서는 이름, 휴대폰 번호, 이메일, 신분증 번호다.

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 6-1-1 | 관리자 | <ul><li>이름과 휴대폰 번호·이메일·신분증 번호를 기존처럼 표시한다.</li></ul> |
| Case 6-1-2 | 별도 pre-order 조회 권한 리더 | <ul><li>휴대폰 번호·이메일·신분증 번호의 라벨과 값 전체를 숨긴다.</li><li>웹에서 해당 리더에게 표시되는 기준과 구분한다.</li></ul> |
| Case 6-1-3 | 일반 리더 | <ul><li>휴대폰 번호·이메일·신분증 번호의 라벨과 값 전체를 숨긴다.</li></ul> |

- 비노출 항목은 마스킹 값·대체 문구·빈 행으로 남기지 않는다. 휴대폰 번호에 함께 표시하는 국가번호도 숨긴다.
- 이름과 나머지 고객 정보는 기존 표시를 유지한다. 화면 비노출은 저장된 고객 정보의 삭제·변경이 아니다.

### 6-2. **Hand raiser·Trade in·S Care +**

- 기본 고객 정보 다음에 Hand raiser 여부를 표시한다. 이 화면은 조회 화면이며 확인·초기화·수정 기능을 추가하지 않는다.
- Trade in과 S Care +는 캠페인의 기존 사용 여부에 따라 표시한다.
- 적용 여부가 Yes인 항목은 기존 상세 정보 펼침·접기 동작을 유지한다. No인 항목에 내용 없는 펼침 기능을 추가하지 않는다.
- Trade in의 기기 식별정보·브랜드·모델·Residual value·신청 앱·증빙, S Care +의 옵션·Protection name·Upsell 등은 기존 등록값과 조건에 따라 표시한다.
- 개인정보 3개 비노출을 이유로 이 영역을 일괄 숨기지 않는다.

### 6-3. **고객 추가 속성·첨부파일**

- 캠페인에서 사용하는 고객 추가 속성을 기존 설정 순서와 유형에 맞춰 표시한다. 사용하지 않는 속성은 표시하지 않는다.
- 단일값·복수값·텍스트·첨부의 기존 표시와 미입력 시 표기를 유지한다.
- 첨부파일은 기존 열람 동작·접근 조건을 유지한다. 이번 변경으로 첨부파일 전체를 제거하거나 새 권한을 부여하지 않는다.
