# 앱 주문 진행 · 직원 모드

진입 경로: Android 앱 > 직원 모드 > Pre-order > 캠페인·Batch·주문 근무지 선택 > 상품 선택 > 주문 진행

---

- 기존 상품 선택·고객 정보(1/2)·결제 정보(2/2) 구성을 유지하고, [Product 및 Allocation 정책](../policy/Policy_04_Product_및_Allocation.md#8-주문에-적용하는-기준)의 주문 가능 근무지 제한을 적용한다.
- 주문 완료 시 MBO 확인은 [주문 및 픽업 처리 정책](../policy/Policy_06_주문_및_픽업_처리.md#2-주문-완료-시-mbo-확인)을 따른다. 변경 결과는 기존 2/2 화면에 반영한다.
- 주문 근무지는 앞선 흐름에서 선택한 값을 사용한다. 상품 선택·주문 입력 화면에 근무지 변경 기능을 추가하지 않는다.

## 1. **상품 선택 화면**

### 1-1. **상단 내비게이션·캠페인 정보**

- 기존 `Pre-Order` 제목과 뒤로 버튼을 유지한다. 뒤로 선택 시 기존 상위 화면으로 돌아간다.
- 회사명, 캠페인명, 선택한 Batch, 메모 순서의 기존 상단 정보를 표시한다.
- 메모가 등록되어 있을 때만 메모 영역을 표시한다.
- 캠페인명·Batch 정보의 기존 표시 및 스크롤 동작을 유지한다.

### 1-2. **상품 검색창**

- 기존 검색창과 `제품명/SKU` 플레이스홀더를 유지한다.
- 검색 기준과 검색어 삭제 동작은 기존과 동일하다.
- 검색 결과에도 주문 근무지별 SKU 노출 제한을 적용한다. 주문할 수 없는 SKU를 검색으로 조회·선택할 수 없어야 한다.

### 1-3. **프로덕트 그룹·상품 카드**

- 기존 프로덕트 그룹명과 그룹별 상품 카드 구조·정렬을 유지한다.
- 카드에는 상품 이미지, 제품명, SKU 코드, 가격, 재고 아이콘·수량·단위를 기존 방식으로 표시한다. 제품명·SKU의 기존 줄 수와 말줄임 처리를 유지한다.
- 상품 이미지를 통한 기존 확대 동작과 재고에 따른 기존 선택 가능 여부를 유지한다.
- 재고 수량은 기존 유통사 단위로 표시하며 근무지별 수량으로 분리하지 않는다.

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 1-3-1 | 주문 근무지가 SKU의 현재 주문 가능 범위에 포함됨 | <ul><li>해당 SKU를 기존 상품 카드로 표시한다.</li><li>기존 재고 등 선택 조건을 충족하면 주문 진행 화면으로 연결한다.</li></ul> |
| Case 1-3-2 | 주문 근무지가 SKU의 현재 주문 가능 범위에 포함되지 않음 | <ul><li>해당 SKU 카드를 표시하지 않는다.</li><li>선택 불가 카드로 남기거나 주문 불가 안내를 카드에 추가하지 않는다.</li></ul> |

- 전체 근무지·특정 근무지의 판정과 Batch 대상 변경 시 적용 범위는 정책을 따른다.
- 진행 중인 주문에서 뒤로 이동해 상품 목록을 다시 조회하는 경우에도 최신 주문 가능 범위를 적용한다.

## 2. **주문 진행 1/2 · 고객 정보 화면**

### 2-1. **상단 내비게이션**

- 기존 `1/2` 표시와 뒤로 버튼을 유지한다.
- 뒤로 선택 시 기존 상품 선택 화면으로 돌아가는 동작을 유지한다.

### 2-2. **선택 상품 영역**

- 선택한 상품의 이미지, 제품명, SKU, 가격, 재고를 기존 구성으로 표시한다.
- 상품 이미지 확대, 가격·할인 및 재고의 기존 표시 기준을 유지한다.

### 2-3. **고객 정보 입력 영역**

- 이름, 휴대폰 번호, 이메일, 신분증 번호의 기존 입력 순서·표시 조건을 유지한다.
- 이메일 아래의 Hand raiser 확인·결과·초기화 동작을 유지한다.
- 기존 OTP, 입력값·필수값 검증을 주문 가능 근무지 검증으로 대체하지 않는다.

### 2-4. **추가 속성·약관 영역**

- 캠페인 설정에 따라 Trade in, S Care +와 고객 추가 속성을 기존 유형·순서·필수 여부에 맞춰 제공한다.
- 약관을 사용하는 경우 기존 전체 동의·개별 동의·상세 보기 동작과 필수 약관 조건을 유지한다.
- 와이어프레임의 추가 속성과 약관은 표시 예시이며 새로운 공통 필수 항목이 아니다.

### 2-5. **하단 다음 버튼·차단 토스트**

- 기존 버튼 활성화 조건과 입력 검증을 유지한다.
- [다음] 선택 시 주문 근무지와 선택 SKU의 최신 주문 가능 여부를 다시 검증한다.

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 2-5-1 | 주문 가능 근무지 검증과 기존 진행 조건을 충족함 | <ul><li>기존 주문 진행 2/2 화면으로 이동한다.</li></ul> |
| Case 2-5-2 | 주문 근무지가 SKU의 현재 주문 가능 범위에서 제외됨 | <ul><li>다음 단계로 이동하지 않는다.</li><li>`이 근무지에서는 선택한 상품을 주문할 수 없습니다.` 토스트를 표시한다.</li><li>입력값을 유지하고 현재 1/2 화면에 머무른다.</li></ul> |

- 차단 안내에 확인 팝업·확인 버튼을 제공하거나 상품 선택 화면으로 자동 이동시키지 않는다.
- 토스트의 표시 방식·노출 시간은 기존 앱 공통 기준을 따른다.

## 3. **주문 진행 2/2 · 결제 정보 화면**

### 3-1. **상단 내비게이션**

- 기존 `2/2` 표시와 뒤로 버튼을 유지한다.
- 뒤로 선택 시 기존 1/2 화면으로 돌아가는 동작을 유지한다.

### 3-2. **선택 상품 영역**

- 선택한 상품의 이미지, 제품명, SKU, 가격, 재고를 기존 구성으로 표시한다.
- 기존 가격·할인 표시와 이미지 확대 동작을 유지한다.
- [완료] 시 MBO 결과 또는 적용 금액이 달라지면 이 영역의 적용 가격과 할인 표시를 갱신한다. MBO 추가 적용 시 기존 할인 양식에 따라 원가·할인 적용 금액·Multibuy를 표시하고, 해제 시 할인 표시를 제거하고 변경된 적용 가격을 표시한다.
- 별도의 변경 전후 금액 비교 영역이나 재확인 화면·팝업을 추가하지 않는다.

### 3-3. **결제 안내·입력 영역**

- 기존 결제 안내와 재고 보류 시간 표시·처리를 유지한다.
- 캠페인에서 사용하는 결제 속성을 기존 유형·순서·필수 여부에 따라 제공한다. 결제 증빙의 기존 첨부·삭제 동작을 유지한다.
- MBO 재확인으로 금액이 갱신되어도 입력한 결제 정보와 첨부파일을 유지한다.
- 와이어프레임의 `Payment method`, `Payment proof`와 입력값은 해당 항목을 사용하는 캠페인의 예시다.

### 3-4. **하단 완료 버튼·안내 토스트**

- 기존 버튼 활성화 조건과 완료 검증을 유지한다.
- [완료] 선택 시 주문 근무지와 선택 SKU의 최신 주문 가능 여부를 다시 검증한다. 1/2에서 통과한 결과만으로 이 검증을 생략하지 않는다.
- [완료] 선택 시 정책에 따라 MBO를 다시 확인하고, 현재 화면에 표시된 결과·금액과 비교한다.
- 최종 저장 시 서버가 [주문 완료 시 Batch 연결 정책](../policy/Policy_06_주문_및_픽업_처리.md#1-주문-완료-시-batch-연결)에 따라 Batch를 결정한다. 이 처리로 별도의 선택·재확인·안내 UI를 추가하지 않으며, 기존 완료 흐름에서 서버가 반환한 최종 Batch 정보를 사용한다.

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 3-4-1 | MBO 결과·금액이 현재 표시와 같고 주문 가능 근무지 검증과 기존 완료 조건을 충족함 | <ul><li>기존 주문 저장·완료 흐름으로 진행한다.</li></ul> |
| Case 3-4-2 | 주문 근무지가 SKU의 현재 주문 가능 범위에서 제외됨 | <ul><li>주문을 완료·저장하지 않는다.</li><li>`이 근무지에서는 선택한 상품을 주문할 수 없습니다.` 토스트를 표시한다.</li><li>입력값을 유지하고 현재 2/2 화면에 머무른다.</li></ul> |
| Case 3-4-3 | MBO 결과 또는 적용 금액이 현재 표시와 달라짐 | <ul><li>해당 요청에서는 주문을 완료·저장하지 않는다.</li><li>선택 상품 영역의 가격·할인 표시를 갱신한다.</li><li>`가격 정보가 변경되었습니다.` 토스트를 표시한다.</li><li>입력값·첨부파일을 유지하고 현재 2/2 화면에 머무른다.</li><li>사용자가 갱신된 금액을 확인한 뒤 기존 [완료] 버튼을 다시 선택할 수 있다.</li></ul> |

- 가격 갱신 후 다시 [완료]를 선택하면 MBO를 재확인한다. 현재 표시와 같고 다른 완료 조건도 충족하면 Case 3-4-1로 진행하며, 다시 달라지면 Case 3-4-3을 반복한다.
- 차단 안내에 확인 팝업·확인 버튼을 제공하거나 이전 단계로 자동 이동시키지 않는다.
- 토스트의 표시 방식·노출 시간은 기존 앱 공통 기준을 따른다.
- 이미 완료된 주문은 이후 주문 가능 근무지 변경을 이유로 수정·취소하거나 조회·픽업을 제한하지 않는다.
