# 앱 주문 목록 · 리더 모드

진입 경로: Android 앱 > 리더 모드 > Pre-order > 캠페인 상세 > 요약 > 프로덕트 그룹 > SKU 선택

---

- SKU별 주문 조회(P03)와 역할별 조회 범위(P04-A)를 같은 주문 목록 화면에 적용한다. 기존 주문 카드·검색·정렬 구성을 유지한다.
- [요약 및 일별 추이 정책](../policy/Policy_08_요약_및_일별_추이.md), [권한 및 조회 범위 정책](../policy/Policy_02_권한_및_조회_범위.md)을 따른다.
- 이 문서는 SKU별 지표에서 진입한 목록을 기준으로 한다. 캠페인 전체 주문 목록 등 기존 진입 경로를 선택 SKU 하나로 제한하는 변경은 아니다.

## 1. **상단 내비게이션·상품 정보**

### 1-1. **뒤로 버튼**

- 내비게이션에는 제목 없이 기존 뒤로 버튼을 제공한다.
- 뒤로 선택 시 진입했던 프로덕트 그룹의 SKU별 지표 화면으로 돌아간다. 진입 당시의 지표·조회 권한·상위 필터 조건을 유지한다.

### 1-2. **프로덕트 그룹명·제품명·SKU 코드**

- 검색창 위에 선택 상품의 프로덕트 그룹명, 제품명, SKU 코드 순서로 표시한다. 그룹명은 제품명보다 작은 보조 텍스트로 표시한다.
- 제품명은 해당 SKU에 등록된 이름을 사용한다. 긴 이름은 상단 영역에서 줄바꿈하여 표시한다.
- 상품 정보 영역에서 다른 그룹이나 SKU를 선택하는 기능은 제공하지 않는다.
- 지표 셀렉트 메뉴와 정보성 지표 문구를 모두 제공하지 않는다. 필터 버튼·적용 필터 배지도 추가하지 않는다.
- 화면에 지표·필터를 표시하지 않아도 진입 시 받은 SKU·지표·조회 권한·필터·기간 조건을 그대로 적용한다.

## 2. **검색창·바코드 버튼**

### 2-1. **검색창·검색어 삭제 버튼**

- 기존 제품명/주문 코드 검색창을 유지한다. 플레이스홀더는 기존 문구인 `제품명/주문 코드`를 사용한다.
- 검색 입력·검색 요청 시점·키보드 처리는 기존 앱 동작을 따른다.
- 검색은 진입 시 받은 조건에 해당하는 주문 안에서 수행한다. 검색어를 바꾸거나 지워도 선택 SKU·진입 지표·권한·상위 필터 조건을 해제하지 않는다.
- 검색·정렬 조건이 바뀌면 이전 조건의 결과가 현재 목록을 덮어쓰지 않도록 기존 요청·결과 적용 처리를 유지한다.
- 검색어가 있으면 기존 삭제 버튼을 표시한다. 선택 시 검색어만 지우고 같은 진입 조건의 주문 목록을 다시 표시한다.

### 2-2. **바코드 버튼**

- 검색창 오른쪽의 기존 바코드 버튼과 카메라 진입 동작을 유지한다.
- 바코드 조회에도 해당 주문 목록의 SKU·지표·권한·상위 필터 범위를 적용한다. 코드 입력 방식이 달라졌다는 이유로 목록 범위를 벗어난 주문을 제공하지 않는다.
- 기존 바코드 조회가 일반 검색과 다른 요청·진입 경로를 사용하는 경우에도 같은 조건이 전달되는지 해당 동작에서 확인한다.

## 3. **주문 개수·정렬 버튼**

- 기존 `주문 (개수)` 표시와 정렬 버튼을 제공한다.
- 개수 표시와 목록의 추가 조회 방식은 기존 동작을 유지한다.
- 최초 정렬은 기존 최신순이며, 정렬 버튼으로 최신순·오래된순을 전환한다. 주문 일시 기준의 기존 정렬을 유지한다.
- 정렬 변경 시 검색어와 SKU·지표·권한·상위 필터 조건을 유지한다. 픽업 수량에서 진입했다고 정렬 기준을 픽업 일시로 바꾸지 않는다.

## 4. **주문 카드 목록**

### 4-1. **표시 대상**

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 4-1-1 | Pre-order 수량에서 진입 | <ul><li>선택 SKU의 대상 주문을 표시한다.</li><li>픽업 전·픽업 완료 주문을 포함하며 공통 집계의 제외 상태를 따른다.</li></ul> |
| Case 4-1-2 | Pre-order 금액에서 진입 | <ul><li>수량 지표와 같은 대상 주문 집합을 표시한다.</li><li>카드에 금액·지표별 수치를 새로 추가하지 않는다.</li></ul> |
| Case 4-1-3 | 픽업 수량에서 진입 | <ul><li>선택 SKU의 대상 주문 중 픽업 완료 주문만 표시한다.</li></ul> |
| Case 4-1-4 | 관리자·별도 pre-order 조회 권한 리더 | <ul><li>기존 회사 내 전체 조회 범위에 진입 SKU·지표·필터 조건을 적용한다.</li></ul> |
| Case 4-1-5 | 일반 리더 | <ul><li>관리 그룹·하위 그룹 구성원의 허용된 주문 범위에 진입 조건을 적용한다.</li><li>현재 소속, 퇴사·삭제 구성원, 일괄 등록 제외 등의 세부 판정은 권한 정책을 따른다.</li></ul> |

- 동일한 조건의 SKU 수치와 연결된 주문 목록의 대상 범위가 일치해야 한다. 검색·정렬·추가 조회로 이 범위를 넓히지 않는다.

### 4-2. **픽업 상태·픽업 일시**

- 카드 상단 왼쪽에 기존 픽업 상태 배지를 표시한다.
- 픽업 완료일 때는 기존 완료 표시와 함께 상단 오른쪽에 픽업 일시를 표시한다. 픽업 전이면 픽업 일시를 표시하지 않는다.
- 배지의 색상·아이콘과 날짜·요일·시간의 표기 방식은 기존 앱 기준을 유지한다.

### 4-3. **상품 이미지·제품명·SKU·주문 코드·주문 일시**

- 카드 본문은 왼쪽 상품 이미지, 오른쪽 제품명·SKU 코드·주문 코드·주문 일시의 기존 구성을 유지한다.
- 제품명은 기존 카드처럼 최대 두 줄로 표시하고 넘으면 말줄임 처리한다. 제품명 아래 SKU 코드를 제공한다.
- 주문 코드와 주문 일시는 기존 `코드`, `일시` 라벨과 함께 표시한다. 주문 일시와 상단 픽업 일시를 혼동하거나 대체하지 않는다.
- 선택 지표에 따른 개별 수치·금액, 고객 개인정보 등 기존 카드에 없는 항목을 추가하지 않는다.

### 4-4. **카드·이미지 선택**

- 카드 선택 시 해당 주문 상세로 이동한다. 주문 상세에도 동일한 조회 권한을 적용한다.
- 상품 이미지는 기존 이미지 확대 동작을 유지한다. 이미지 선택으로 주문 상세까지 중복 실행되지 않도록 한다.
- 주문 상세의 정보 표시와 작업 버튼은 [앱 주문 상세](App(L)_dc_06_주문_상세.md)를 따른다. 주문 목록에 접근할 수 있다는 이유로 수정·삭제 등의 권한을 추가하지 않는다.
