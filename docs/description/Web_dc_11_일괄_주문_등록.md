# 일괄 주문 등록

진입 경로: 대시보드 > pre-order > 캠페인 상세 > 주문 목록 > 일괄 작업 > 일괄 업로드

---

- 기존 파일 기반 일괄 업로드 화면에 신규 주문의 주문 가능 근무지 검증을 추가한다. 별도 단건 등록 화면을 신설하지 않는다.
- 주문 가능 여부와 온라인 주문의 검증 제외 기준은 [Product 및 Allocation 정책](../policy/Policy_04_Product_및_Allocation.md#8-주문에-적용하는-기준)을 따른다.
- 기존 관리자 계열의 등록 권한을 유지한다. 리더의 조회 권한 확대만으로 일괄 작업 권한을 부여하지 않는다.
- 파일 양식·입력 항목·표의 열 순서·필수값·재고 등 이번 변경 외의 검증과 화면 동작은 유지한다.

## 1. **상단 헤더**

### 1-1. **제목·뒤로 가기**

- 기존 ‘일괄 업로드’ 제목과 뒤로 가기 동작을 유지한다. 이탈 시 입력값 처리도 기존 기준을 따른다.

### 1-2. **저장 버튼**

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 1-2-1 | 등록할 행이 없거나 검증 오류가 남아 있음 | <ul><li>[저장]을 비활성화한다.</li><li>주문 가능 근무지 오류도 기존 행별 오류 판정에 포함한다.</li><li>오류 행만 보기의 선택 여부와 관계없이 전체 등록 대상 행을 기준으로 판단한다.</li></ul> |
| Case 1-2-2 | 등록할 행이 있고 모든 검증 통과 | <ul><li>기존 조건에 따라 [저장]을 활성화한다.</li><li>기존 저장 확인창을 거쳐 등록을 요청한다.</li><li>최종 저장 시 현재 저장된 주문 가능 근무지 설정으로 다시 검증한다. 파일 적용 시 통과했다는 이유로 최종 검증을 생략하지 않는다.</li></ul> |
| Case 1-2-3 | 저장 시 주문 가능 근무지 검증에서 한 행 이상 실패 | <ul><li>검증을 통과한 정상 주문은 저장하고, 실패한 행만 입력값을 유지한 채 편집 표에 남긴다.</li><li>기존 저장 오류 응답 처리와 공통 안내를 유지하고, 반환된 오류 행의 상품·주문 근무지 셀에 3-2의 빨간 테두리를 표시한다.</li><li>오류가 남아 있는 동안 [저장]을 비활성화한다.</li></ul> |
| Case 1-2-4 | 모든 행 등록 성공 | <ul><li>기존 성공 안내와 캠페인 상세 복귀·목록 갱신을 유지한다.</li></ul> |

- 시스템 오류·통신 실패를 등록 성공으로 처리하지 않는다. 재시도와 오류 응답 후 표시 대상은 기존 일괄 등록 처리를 유지한다.

## 2. **파일 업로드 영역**

### 2-1. **영역 펼침·접힘**

- 기존 파일 업로드 영역의 펼침·접힘을 유지한다. 파일 적용 후 하단 편집 표를 표시하는 기존 흐름을 따른다.

### 2-2. **플랫폼 선택·양식 다운로드**

- 기존 플랫폼 선택과 해당 플랫폼의 양식 다운로드를 유지한다.
- 오프라인 주문에는 주문 근무지와 SKU의 주문 가능 여부 검증을 적용한다. 주문 근무지를 사용하지 않는 온라인 주문에는 해당 검증을 적용하지 않는다.
- 온라인 주문의 다른 필수값·파일·주문 검증은 유지한다.

### 2-3. **파일 선택·적용 버튼**

- 기존 파일 선택·파일 정보·제거·[적용] 버튼 및 파일 검증을 유지한다.
- 파일 적용 시 각 행의 주문 근무지와 SKU 조합을 검증하고 결과를 하단 표의 행별 오류 상태에 반영한다.
- 오류가 있는 행도 기존 편집 표에서 수정할 수 있도록 표시한다. 오류 표현은 3-2를 따른다.

## 3. **주문 편집 표**

### 3-1. **주문 개수·오류 행만 보기·행 선택 및 삭제**

- 기존 주문 개수·체크박스·전체 선택·선택 행 삭제 동작을 유지한다. 여기서 삭제하는 대상은 등록 전 편집 표의 행이며, 이미 저장된 주문을 삭제하는 동작과 구분한다.
- 기존 ‘오류 행만 보기’ 기능에 주문 가능 근무지 오류를 포함한다. 켜면 현재 검증 오류가 있는 행만 표시하고, 끄면 전체 등록 대상 행을 표시한다.
- 오류 행만 보는 중 수정으로 해당 행의 모든 오류가 해제되면 표시 대상에서 제외한다. 다른 오류가 남아 있다면 계속 표시한다.
- 전체 오류가 해제되면 오류 행만 보기를 해제하고 전체 행을 표시하는 기존 동작을 유지한다.

### 3-2. **상품·주문 근무지 셀**

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 3-2-1 | 오프라인 주문이며 주문 가능한 조합 | <ul><li>기존 상품·주문 근무지 선택 셀을 표시한다.</li><li>다른 검증 오류가 없으면 기본 테두리를 표시한다.</li></ul> |
| Case 3-2-2 | 오프라인 주문이며 주문 불가 조합 | <ul><li>해당 행의 상품·주문 근무지 셀 모두에 기존 오류 스타일의 빨간 테두리를 표시한다.</li><li>입력한 값은 유지한다.</li><li>셀 아래 오류 문구·별도 사유 열·새 오류 툴팁은 추가하지 않는다.</li></ul> |
| Case 3-2-3 | 상품 또는 주문 근무지 수정 | <ul><li>변경된 값과 현재 행의 다른 값을 조합해 주문 가능 여부를 다시 검증한다.</li><li>주문 가능한 조합이면 해당 검증 오류를 해제한다.</li><li>기존의 다른 검증 오류까지 함께 제거하지 않는다.</li></ul> |
| Case 3-2-4 | 주문 근무지를 사용하지 않는 온라인 주문 | <ul><li>기존처럼 주문 근무지 열을 표시하지 않는다.</li><li>주문 가능 근무지 제한으로 상품 셀을 오류 처리하지 않는다.</li><li>기존 상품·온라인 주문 검증은 유지한다.</li></ul> |

- 주문 가능 근무지 설정만을 이유로 선택 팝업의 후보를 새로 축소하지 않는다. 기존 후보 제공 범위를 유지하고 선택한 값의 조합을 검증한다.
- MBO·결제·고객 정보 등 기존 열과 순서를 유지한다.

## 4. **셀의 선택 팝업**

### 4-1. **상품 선택 팝업**

- 상품 셀을 누르면 기존 캠페인 상품 단일 선택 팝업을 연다. 기존 후보·검색·선택·적용·취소 동작을 유지한다.
- 적용 시 선택한 상품 정보를 행에 반영하고, 해당 행의 주문 근무지와 새 SKU 조합을 다시 검증한다. 상품 변경에 따른 기존 연관 필드 처리도 유지한다.

### 4-2. **근무지 선택 팝업**

- 주문 근무지 셀을 누르면 기존 공통 근무지 선택 팝업을 단일 선택 방식으로 연다.
- 제목은 기존 ‘근무지’를 유지하며, 근무지 목록·검색·현재 선택값과 하단 [취소]·[적용]을 기존 구성으로 제공한다.
- [적용] 시 선택한 근무지를 해당 행에 반영하고 현재 SKU와의 주문 가능 여부를 다시 검증한다. 다른 행의 근무지를 함께 변경하지 않는다.
- [취소] 시 팝업에서 변경한 선택을 반영하지 않고 기존 셀 값과 오류 상태를 유지한다.
- 이 동작은 신규 일괄 등록 화면 기준이다. 기존 주문의 일괄 수정에서는 주문 근무지를 읽기 전용으로 표시하는 기존 동작을 유지하며, P05의 주문 가능 근무지 검증을 추가하지 않는다.
