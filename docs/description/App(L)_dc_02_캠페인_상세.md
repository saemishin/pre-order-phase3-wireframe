# 앱 캠페인 상세 · 리더 모드

진입 경로: Android 앱 > 리더 모드 > Pre-order > 캠페인 목록 > 캠페인 선택

---

- 캠페인 상세의 요약·추이 탭을 한 화면으로 작성한다. 상품별 조회·일별 추이(P03)와 일반 리더의 담당 범위 조회(P04-A)를 함께 적용한다.
- [요약 및 일별 추이 정책](../policy/Policy_08_요약_및_일별_추이.md), [권한 및 조회 범위 정책](../policy/Policy_02_권한_및_조회_범위.md), [캠페인 및 Batch 정책](../policy/Policy_03_캠페인_및_Batch.md)을 함께 적용한다.

## 1. **상단 내비게이션·캠페인 정보**

### 1-1. **뒤로·필터·안내 버튼**

- 기존 뒤로·필터·캠페인 안내 버튼과 각 진입 동작을 유지한다.
- 뒤로 선택 시 기존 진입 경로에 따라 이전 화면으로 돌아간다.
- 필터 아이콘은 요약·추이에서 공통으로 제공한다. 기존 유통사·도·도시·근무지·SKU·Batch 필터 팝업을 사용하며 후보 목록·선택 UI를 새로 개편하지 않는다.
- 필터 적용·해제 시 허용된 주문 범위 안에서 결과를 갱신한다. 적용된 필터의 표시와 해제 동작은 기존 방식을 유지한다.
- Batch 필터는 표시 주간을 유지하면서 선택 Batch 소속 주문의 실적만 좁힌다. 기존 Android 요약 요청에 `batchFilter = null`이 고정된 조사 결과가 있으므로, 공통 필터가 요약·추이의 집계 요청에 실제 전달되는지 함께 확인한다. 버튼 표시만 유지하고 집계 조건 전달을 생략하지 않는다.

### 1-2. **상태·기간·캠페인명**

- 기존 상태 배지, 캠페인 기간, 캠페인명 표시를 유지한다.
- 캠페인 기간 표시는 추이의 선택 주간으로 대체하지 않는다. 추이 주간은 아래 차트 카드에서 별도로 표시한다.
- 기간 종료·집계 시작 전의 상태를 표현하더라도 리더의 캠페인 목록 조회 상태 범위를 확대하지 않는다.

## 2. **요약·추이 탭**

- 상단에 `요약`, `추이` 탭을 제공하고 최초 상세 진입 시 `요약`을 선택한다.
- 탭을 전환해도 캠페인·조회 권한·기존 필터는 유지한다. 전환 자체로 데이터를 갱신하지 않는다.
- 같은 상세 화면 안에서 왕복할 때 요약의 펼침 상태, 추이의 선택 지표·주간·보기별 상품 선택을 유지한다. 상세 화면을 나갔다 다시 진입하는 경우까지 상태를 영구 저장하지 않는다.
- 기존처럼 진입·재진입 시 조회한다. 최근 업데이트 시각·갱신 버튼은 제공하지 않는다. 주간·지표·상품·필터 변경에 필요한 데이터 조회는 해당 조건에 맞춰 처리한다.

## 3. **요약 지표 카드**

### 3-1. **지표명·수치·실적 비율**

- `Pre-order 수량`, `Pre-order 금액`, `픽업 수량` 세 지표를 기존 순서로 제공한다. 기존 숫자·통화·비율·진행 막대·도움말 표시 방식을 유지한다.
- 오프라인 대상·상태·금액 등 집계 정의는 요약 및 일별 추이 정책을 따른다. 서버가 반환하는 전체 온·오프라인 합계를 앱 카드에 그대로 대입하지 않는다.

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 3-1-1 | 관리자·별도 pre-order 조회 권한 리더 | <ul><li>기존 회사 내 전체 조회 범위에 필터를 적용한 실적을 표시한다.</li></ul> |
| Case 3-1-2 | 일반 리더 | <ul><li>관리 그룹·하위 그룹 구성원의 허용된 주문만 집계한다.</li><li>권한 정책의 현재 소속·퇴사 및 삭제 구성원·일괄 등록 제외 기준을 적용한다.</li></ul> |
| Case 3-1-3 | 조회 가능한 주문 또는 필터 결과가 0건 | <ul><li>세 지표 카드를 유지하고 수량·금액을 0으로 표시한다.</li><li>실제 주문 없음과 담당 범위 내 주문 없음을 구분하지 않는다.</li></ul> |

- 주문 수량·금액의 배정 분모는 기존 기준을 유지한다. 픽업 비율의 분모는 같은 조회 범위와 필터 조건에 해당하는 오프라인 주문 수량이다. 분모 0 등 기존 비율 처리도 유지한다.

### 3-2. **펼침·접힘 버튼과 그룹별 목록**

- 최초에는 세 지표의 그룹별 목록을 모두 접힌 상태로 표시한다.
- 각 지표에서 펼침 버튼을 선택하면 해당 지표의 프로덕트 그룹별 수치를 카드 아래에 표시하고 다시 선택하면 접는다. 여러 지표를 동시에 펼칠 수 있다.
- 현재 필터 범위 안의 그룹은 실적 0이어도 표시한다. 대시보드에서 설정한 프로덕트 그룹 순서를 유지한다.
- 그룹 행에는 그룹명, 해당 지표의 수치, 상세 진입 꺾쇠를 표시한다.
- 그룹 행 선택 시 해당 그룹의 SKU별 지표 화면으로 이동한다. 선택 지표·그룹과 현재 조회 권한·필터를 전달한다. 요약의 그룹 → SKU → 주문 목록 흐름은 추이 탭과 별도로 유지한다.
- SKU별 지표 화면의 세부 요소는 [SKU별 지표 디스크립션](App(L)_dc_04_SKU별_지표.md)을 따른다.

### 3-3. **상세보기 버튼**

- 기존 상세보기 버튼의 노출 조건과 전체 주문 목록 진입 동작을 유지한다.
- 이동한 주문 목록에도 같은 조회 권한과 기존 필터 조건을 적용한다. 일반 리더의 담당 범위를 벗어난 주문 목록으로 연결하지 않는다.

## 4. **추이 보기 탭·프로덕트 그룹 선택**

### 4-1. **프로덕트 그룹 / SKU 탭**

- 탭 이름은 `프로덕트 그룹`, `SKU`로 표시한다. ‘별’을 붙이지 않는다.
- 추이 최초 진입 시 `프로덕트 그룹`을 선택한다. 두 보기의 상품 선택 상태는 각각 유지한다.
- 아래에 ‘프로덕트 그룹’, ‘여러 개 선택 가능’, ‘1개 선택’ 같은 보조 안내를 반복 표시하지 않는다.

### 4-2. **프로덕트 그룹 선택 버튼**

- 현재 필터의 상품 범위에 해당하는 그룹을 대시보드 설정 순서로 표시한다. 실적이 0이라는 이유로 후보를 제외하지 않는다.
- 선택 버튼이 가로 영역을 넘으면 가로 스크롤로 탐색한다.

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 4-2-1 | 프로덕트 그룹 보기 최초 진입 | <ul><li>전체 그룹을 선택한다.</li><li>‘전체’ 버튼과 그룹별 버튼을 제공하고 선택 항목은 체크로 구분한다.</li></ul> |
| Case 4-2-2 | 프로덕트 그룹 보기에서 선택 변경 | <ul><li>여러 그룹을 함께 선택할 수 있다.</li><li>‘전체’ 선택 시 현재 후보 전체를 선택한다.</li><li>마지막으로 선택된 그룹은 해제할 수 없다. 선택 표시를 유지하고 해제 동작만 막는다.</li></ul> |
| Case 4-2-3 | SKU 보기 최초 진입 | <ul><li>첫 번째 유효 그룹 하나를 선택한다.</li><li>그룹 단일 선택 방식으로 표시하며 ‘전체’ 버튼은 제공하지 않는다.</li></ul> |
| Case 4-2-4 | SKU 보기에서 그룹 변경 | <ul><li>선택한 그룹의 SKU 중 기존 필터에 해당하는 항목들을 표시한다.</li><li>다른 그룹을 선택하면 선택 그룹과 차트·합계·범례를 함께 변경한다.</li></ul> |
| Case 4-2-5 | 상단 필터 변경으로 선택 그룹이 조회 대상에서 사라짐 | <ul><li>SKU 보기에서는 첫 유효 그룹으로 변경한다.</li><li>프로덕트 그룹 보기에서는 남아 있는 선택과 현재 후보의 교집합을 적용한다. 유효한 선택이 하나도 없고 후보가 있으면 첫 유효 그룹을 선택한다.</li><li>후보가 없는 경우 임의의 그룹을 만들어 선택하지 않는다.</li></ul> |

- 보기·그룹 변경으로 선택 지표와 표시 주간을 초기화하지 않는다.

## 5. **추이 지표 선택**

- 지표 선택은 주간 합계·그래프를 묶은 카드 **밖의 상단**에 제공한다. 선택 지표는 합계와 그래프에 공통 적용한다.
- 선택 항목은 `Pre-order 수량`, `픽업 수량`이며 최초에는 `Pre-order 수량`을 선택한다. 금액은 추이 선택 항목에 포함하지 않는다.
- 선택 필드를 누르면 앱의 단일 선택 하단 목록 팝업을 열고 현재 선택 항목에 체크를 표시한다. 항목 선택 시 적용하고 닫으며, 바깥 영역 또는 뒤로로 닫으면 기존 선택을 유지한다.
- 기존 Sales Target의 단일 항목 선택과 `SDGListBottomSheet` 패턴을 참고한다. HTML 목업의 브라우저 기본 select를 실제 앱 사양으로 사용하지 않는다.
- 지표 변경 시 표시 주간·상품 선택·기존 필터를 유지하고 현재 조건의 합계·차트 수치를 함께 변경한다.

## 6. **주간 날짜·합계·그래프 카드**

- 하나의 카드 안에 **날짜 선택 → ‘주간 합계’ 라벨 → 합계 숫자 → 일별 그래프 → 색상 범례** 순서로 배치한다.

### 6-1. **날짜 표시·이전 주·다음 주 버튼**

- 카드 최상단에 월~일 날짜 구간과 이전 주·다음 주 버튼을 제공한다. 주간 단위로 이동하며 달력으로 임의 기간을 지정하는 기능은 제공하지 않는다.
- 날짜 구간은 목업 기준 `yyyy.mm.dd ~ mm.dd`로 표시한다. 날짜 형식의 현지화는 기존 앱 표기 기준을 따른다.
- 이전·다음 주의 7일 중 조회 가능한 실적 날짜가 하나도 없으면 해당 이동 버튼을 비활성화한다.
- 주간 이동 시 선택 지표·상품·필터를 유지하고 합계와 그래프를 함께 갱신한다.

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 6-1-1 | 전체 조회 기간 진행 중 | <ul><li>오늘이 포함된 월~일 주간을 최초 표시한다.</li></ul> |
| Case 6-1-2 | 전체 조회 기간 종료 | <ul><li>마지막 조회 가능 날짜가 속한 월~일 주간을 최초 표시한다.</li></ul> |
| Case 6-1-3 | 첫 주 또는 마지막 주가 일부 날짜만 포함 | <ul><li>월~일 7칸을 유지한다.</li><li>예: 금요일 시작·토요일 조회라면 월~목은 기간 밖, 금~토는 실제 실적, 일요일은 미래 날짜로 구분한다.</li></ul> |
| Case 6-1-4 | 모든 Batch의 주문·픽업 기간이 시작 전 | <ul><li>이전·다음 주 버튼을 비활성화하며 실제 실적 0건으로 표현하지 않는다.</li></ul> |

### 6-2. **주간 합계**

- 숫자 **위에** ‘주간 합계’를 표시한다. 숫자는 현재 주간·지표·상품·권한·필터 조건에 해당하는 일별 합계의 총합이다.
- 조회 가능한 날짜가 있고 실적이 없으면 0, 조회 가능한 기간 자체가 없으면 ‘—’로 표시한다.
- 선택 그룹 안내나 프로덕트 그룹명을 합계 아래에 반복 표시하지 않는다. 상품 범위는 상단 선택 버튼으로 확인한다.

### 6-3. **일별 그래프**

- 프로덕트 그룹·SKU 보기 모두 제목은 **‘일별 추이’**로 표시한다.
- 가로축은 월~일 7개 날짜, 세로축은 선택한 지표의 수량이다. 날짜와 요일을 표시하고 날짜마다 상품별 색상을 쌓은 막대로 표현한다.
- 프로덕트 그룹 보기에서는 선택 그룹별 수량, SKU 보기에서는 선택 그룹 안의 조회 대상 SKU별 수량을 쌓는다.
- 막대 위 숫자는 해당 날짜에 표시하는 상품들의 전체 합계다. 개별 색상 구간마다 숫자를 반복 표시하지 않는다.
- 막대 선택으로 상세 수치 팝업이나 주문 목록에 진입하는 기능은 제공하지 않는다. 특정 SKU의 수치는 기존 상단 SKU 필터로 좁혀 확인한다.

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 6-3-1 | 조회 가능한 날짜·실적 있음 | <ul><li>해당 수량의 쌓은 막대와 날짜별 합계를 표시한다.</li></ul> |
| Case 6-3-2 | 조회 가능한 날짜·실적 없음 | <ul><li>해당 날짜의 수량을 0으로 표시한다. 전 날짜 0건이어도 날짜 축과 조회 대상 범례를 유지한다.</li></ul> |
| Case 6-3-3 | 전체 조회 기간 밖 또는 미래 날짜 | <ul><li>막대를 그리지 않고 ‘—’로 표시한다.</li><li>날짜를 비활성 표현으로 구분한다. 0건으로 표시하지 않는다.</li></ul> |

- 그래프 아래 ‘기간 밖·미래 날짜는 —로 표시합니다.’ 안내 문구는 제공하지 않는다.
- 날짜 집계는 고객사 시간대의 날짜 시작 이상·다음 날짜 시작 미만으로 확인한다. 기존 날짜 검색의 `23:59:00` 종료 경계를 그대로 복제해 마지막 분의 주문·픽업을 누락하지 않는다. 기존 공통 날짜 유틸 전체를 수정하는 범위로 확대하지 않는다.
- 기존 Android `MPAndroidChart` 재사용 가능성을 조사했으며 7칸·쌓은 막대·합계 표시의 구현 근거는 확인했다. 실제 앱 적용 시 전부 0인 주, 큰 수치, 다수 SKU, 지표·필터 전환 후 합계·색상 정합성을 확인한다. 기존 방문 기록의 0높이 막대 처리로 0값·미래 날짜에 임의의 막대가 생기지 않도록 한다. 구현이 어렵다는 이유로 날짜별 합계를 임의 생략하지 않고 해당 표현을 개발 검토한다.

### 6-4. **색상 범례**

- 그래프 아래에 **한 행에 항목 하나씩** 표시한다. 프로덕트 그룹·SKU 보기 모두 동일하게 적용한다.
- 프로덕트 그룹은 색상 표식과 그룹명을 표시한다.
- SKU는 색상 표식 옆에 **등록된 제품명(Product name)**, 그 아래에 **SKU 코드**를 표시한다. 색상·RAM·ROM을 별도 조합한 라벨로 대체하지 않는다. 제품명에 포함된 정보는 그대로 표시한다.
- 그룹·SKU 순서는 대시보드 설정 순서를 유지한다. 실적 0인 항목도 현재 조회 상품 범위에 포함되면 유지한다.
- 범례는 정보 표시 전용이며 체크·선택 해제 기능을 제공하지 않는다. 항목이 많으면 화면의 세로 스크롤로 확인한다.
- 긴 제품명·코드와 다수 SKU가 잘리거나 겹치지 않도록 확인한다. 기존 라이브러리 범례의 줄바꿈 지원만으로 제품명·SKU 코드의 두 줄 구성 및 한 행 한 항목 배치를 충족하는지 검토하고, 필요하면 차트 아래 별도 앱 목록으로 구성한다. 기본 범례 제약에 맞춰 제품명이나 SKU 코드를 누락하지 않는다.
