# 캠페인 Product

진입 경로: 대시보드 > pre-order > 캠페인 생성 또는 캠페인 수정 > Product 단계

---

- 캠페인의 프로덕트 그룹과 그룹별 상품을 설정하는 화면이다.
- 그룹 수는 [캠페인 및 Batch 정책](../policy/Policy_03_캠페인_및_Batch.md), 그룹 관리·검증은 [Product 및 Allocation 정책](../policy/Policy_04_Product_및_Allocation.md)을 따른다.
- 프로덕트 그룹 탐색·추가·삭제와 SKU별 주문 가능 근무지 설정을 제공한다.

## 2. **프로덕트 그룹 탭 영역**

| 구분 | 정의 |
| --- | --- |
| Body | <ul><li>상단에 프로덕트 그룹 탭과 [+] 버튼을 표시한다.</li><li>탭 아래에는 선택한 그룹의 설정 카드 하나만 표시한다.</li><li>카드 상단 공통 레이블은 Product Group이다. 탭 위에는 같은 레이블을 추가하지 않는다.</li></ul> |

### 2-1. **그룹 탭·탭명**

- 그룹 하나당 탭 하나를 등록 순서대로 표시한다. 기존 캠페인은 저장된 그룹 순서를 사용한다. 선택한 탭을 구분하며 최초 진입 시 첫 번째 그룹을 표시한다.
- 그룹명은 한 줄로 표시한다. 긴 이름은 말줄임 처리한다. 해당 프로덕트 그룹의 탭을 선택하면 본문에 그 그룹의 설정 카드가 표시되며, 카드의 그룹명 입력 영역에서 전체 이름을 확인할 수 있다.
- 탭 선택 시 해당 그룹의 설정 카드로 전환한다. 다른 그룹에서 작성한 값은 유지한다.
- 탭 영역과 카드 내부 SKU 테이블의 가로 스크롤은 각각 독립적으로 동작한다.

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 2-1-1 | 이름 입력 전 | <ul><li>탭에 Product Group을 연한 글씨로 표시한다. 선택된 탭이어도 안내 글씨는 연하게 유지한다.</li><li>실제 그룹명은 빈 값이며 안내 표시를 저장하지 않는다.</li></ul> |
| Case 2-1-2 | 이름 입력·수정 | <ul><li>입력한 그룹명을 즉시 탭에 반영하고 안내 표시보다 진한 글씨로 표시한다.</li><li>이름을 비우면 Case 2-1-1로 돌아간다.</li></ul> |

- 탭 변경 자체로 서버 저장하거나 입력값을 폐기하지 않는다.

### 2-2. **탭 좌우 이동 버튼**

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 2-2-1 | 모든 탭이 표시 영역 안에 들어옴 | <ul><li>좌우 이동 버튼을 표시하지 않는다.</li></ul> |
| Case 2-2-2 | 탭이 표시 영역을 넘침 | <ul><li>탭 영역의 좌우 이동 버튼을 표시한다. 버튼으로 탭 목록을 가로 이동한다.</li><li>목록을 이동하는 것만으로 선택 그룹을 변경하지 않는다.</li><li>그룹 추가·삭제·이름 변경·창 너비 변경에 따라 넘침 여부를 다시 판단한다.</li><li>추가 또는 오류 검증으로 다른 그룹이 선택되면 해당 탭이 보이도록 이동한다.</li></ul> |

### 2-3. **그룹 추가 버튼**

- 탭 우측에 [+] 아이콘 버튼을 고정 표시한다. 버튼의 기능명은 ‘프로덕트 그룹 추가’다.

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 2-3-1 | 그룹 20개 미만 | <ul><li>[+]를 활성화한다.</li><li>선택 시 마지막에 새 그룹 탭을 추가하고 해당 그룹을 선택한다.</li><li>이름 입력 전 탭 표시는 Case 2-1-1을 따르며 본문은 기존 신규 그룹의 업로드 전 상태로 표시한다.</li></ul> |
| Case 2-3-2 | 그룹 20개 | <ul><li>[+]를 비활성화한다.</li><li>그룹 삭제 후 20개 미만이 되면 다시 활성화한다.</li></ul> |

### 2-4. **그룹 삭제 버튼**

- 기존 그룹명 입력 옆 더보기 메뉴를 제거하고 삭제 진입점을 탭으로 이동한다.
- 그룹이 2개 이상이면 각 탭의 그룹명 옆에 [×] 삭제 버튼을 표시한다. 그룹이 1개이면 표시하지 않는다.
- [×]를 누르면 해당 버튼이 있는 탭의 그룹을 대상으로 삭제 확인창을 연다. 예를 들어 A 그룹을 보고 있는 상태에서 B 그룹 탭의 [×]를 누르면 삭제 대상은 B 그룹이다.

#### 2-4-1. **삭제 확인 모달**

| 구분 | 정의 |
| --- | --- |
| Body | <ul><li>기존 문구 ‘삭제하시겠습니까?’를 표시한다.</li></ul> |
| Footer | <ul><li>본문과 구분선을 두고 우측에 [취소]·[삭제]를 순서대로 표시한다.</li><li>기존 양식에 따라 취소는 회색, 삭제는 빨간색 버튼으로 표시한다.</li></ul> |

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 2-4-1-1 | [취소] 선택 | <ul><li>확인창을 닫는다. 그룹과 기존 선택 상태는 유지한다.</li></ul> |
| Case 2-4-1-2 | 현재 선택 그룹의 [삭제] 확정 | <ul><li>기존 삭제 처리를 수행하고 해당 탭과 설정 카드를 제거한다.</li><li>앞 그룹을 선택한다. 첫 번째 그룹이었다면 남은 첫 번째 그룹을 선택한다.</li></ul> |
| Case 2-4-1-3 | 다른 그룹의 [삭제] 확정 | <ul><li>기존 삭제 처리를 수행하고 대상 그룹 탭을 제거한다.</li><li>현재 선택한 그룹과 그 입력값을 유지한다.</li></ul> |

## 3. **그룹 설정 카드**

- 카드 상단에 Product Group 레이블, 그 아래 그룹명 입력 및 기존 설정 영역을 표시한다.

- Category, Multi Buy Offer, Property, Upload, SKU 테이블, 이미지 업로드는 기존 구성을 유지하고, 주문 가능 근무지 속성과 열을 추가한다. 카테고리·캠페인 설정에 따른 기존 열 구성은 유지한다.
- 상품 초기화는 기존 동작을 유지한다.

### 3-1. **그룹명 입력 필드**

- 그룹명 입력값은 해당 그룹의 탭명에 연동한다. 이름 길이·필수·중복 등의 검증 기준은 기존 방식을 따른다.

### 3-2. **Property 영역의 주문 가능 근무지 속성**

- 상품 업로드 전 Property 영역에 ‘주문 가능 근무지’를 고정 속성으로 제공한다. 필수 표시 [*]를 붙이고 삭제 버튼은 제공하지 않는다.
- 상품 카테고리와 관계없이 모든 프로덕트 그룹에 표시한다.
- 고정 속성의 마지막인 Image(KV) 다음에 배치한다. 커스텀 속성은 주문 가능 근무지 뒤에 표시하며, 새 커스텀 속성도 목록 마지막에 추가한다.
- 속성명 옆 도움말 아이콘에 마우스를 올리면 다음 툴팁을 표시한다.

> 상품별로 주문할 수 있는 근무지를 설정합니다. 기본값은 batch의 모든 대상 근무지입니다.

### 3-3. **Upload 영역·파일 처리 상태**

- 파일은 해당 프로덕트 그룹 단위로 처리한다. 기존 양식 다운로드·파일 검증·적용·삭제 및 초기화 동작을 유지한다.

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 3-3-1 | 파일 업로드 전 | <ul><li>그룹의 기존 설정 영역과 Property를 유지하고 Upload 영역에 양식 다운로드·파일 업로드 구성을 표시한다.</li><li>Property의 주문 가능 근무지 속성은 3-2의 기준을 따른다.</li></ul> |
| Case 3-3-2 | 파일 처리 중 | <ul><li>처리 중인 그룹의 설정 카드에서 Property를 유지한다.</li><li>Upload 영역의 파일명 자리에 긴 막대 스켈레톤을 표시한다.</li><li>SKU 테이블은 기존 헤더·행별 셀 형태의 스켈레톤으로 표시한다.</li><li>버튼 활성화·편집 제한은 기존 파일 처리 기준을 유지한다.</li></ul> |
| Case 3-3-3 | 파일 적용 완료·기존 데이터 조회 | <ul><li>기존 파일 정보와 해당 그룹의 SKU 테이블을 표시한다.</li><li>주문 가능 근무지 열은 3-4의 기준을 따른다.</li></ul> |

- 업로드 오류·재시도와 입력값 검증 및 편집 가능 조건은 기존 동작을 유지한다.

### 3-4. **SKU 테이블의 주문 가능 근무지 열**

- 테이블 가장 오른쪽에 ‘주문 가능 근무지’ 열을 추가하고 필수 표시 [*]를 붙인다.
- Image 열과 주문 가능 근무지 열을 오른쪽에 고정한다. 가운데 상품 정보 영역을 가로 스크롤해도 두 열은 계속 표시한다.
- 셀에는 전체·특정 옵션을 직접 나열하지 않고 아래 요약값을 표시한다. 셀을 선택하면 해당 SKU의 [주문 가능 근무지 팝업](Web_dc_06_주문_가능_근무지_선택.md)을 연다.
- 신규 업로드한 SKU의 기본 표시는 ‘전체’다. 화면에서만 설정하며 업로드 파일에는 이 열을 추가하지 않는다.

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 3-4-1 | 전체 근무지 | <ul><li>‘전체’로 표시한다.</li></ul> |
| Case 3-4-2 | 특정 근무지, 0~999개 | <ul><li>개수를 배지로 표시한다. 예: ‘0개’, ‘2개’, ‘999개’.</li><li>근무지명이나 ‘선택’ 접두어는 표시하지 않는다.</li></ul> |
| Case 3-4-3 | 특정 근무지, 1,000개 이상 | <ul><li>배지에 ‘+999개’로 표시한다.</li></ul> |

- 개수는 현재 Batch 대상과 겹치는 실제 주문 가능 근무지를 기준으로 표시한다. Batch 밖의 선택을 보존하는 데이터 기준은 [Product 및 Allocation 정책](../policy/Policy_04_Product_및_Allocation.md)을 따른다.
- 팝업에서 적용한 값은 해당 SKU의 셀에 반영한다. 다른 SKU에 일괄 적용하는 기능은 제공하지 않는다.
