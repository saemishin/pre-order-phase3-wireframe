# 캠페인 Hand Raiser

진입 경로: 대시보드 > pre-order > 캠페인 생성 또는 캠페인 수정 > Hand Raiser 단계

---

- 파일 업로드·성공 건 반영·실패 파일·주문 판정은 [Hand Raiser 정책](../policy/Policy_05_Hand_raiser.md)을 따른다.
- 기존 이메일 전체 목록을 표시하던 영역을 파일 정보와 처리 결과로 바꾼다. 생성·수정에 동일한 업로드 구성을 사용하며 기존 캠페인 수정 권한·상태 제한은 유지한다.

## 1. **상단 헤더·단계 표시**

| 구분 | 정의 |
| --- | --- |
| Header | 기존 임시 저장·닫기 및 Timeline / Product / Allocation / Hand Raiser 단계 표시를 유지한다. |

- 임시 저장·캠페인 닫기의 기존 저장·이탈 기준을 유지한다.

## 2. **Customer Info 카드**

| 구분 | 정의 |

### 2-1. **공통 파일 업로드 영역**

- 아래 구성은 캠페인 상세의 [추가 업로드](Web_dc_09_Hand_raiser_명단_관리.md#3-추가-업로드-팝업) 팝업에서도 사용한다.
- 템플릿의 이메일 입력 양식을 유지하고 Excel·CSV 파일을 지원한다. 생성·수정·추가 업로드에 서로 다른 이메일 입력 양식을 두지 않는다.
- 파일 업로드 안내는 ‘이메일을 입력한 파일(Excel, CSV)을 업로드해 주세요.’로 표시한다. 업로드 버튼 아래에 별도 안내를 중복 표시하지 않는다.

#### 2-1-1. **양식 다운로드·업로드 버튼**

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 2-1-1-1 | 파일 업로드 전 | <ul><li>STEP 1의 양식 다운로드와 STEP 2의 파일 업로드를 좌우로 제공한다.</li><li>[Download] 버튼 : 이메일 입력 양식을 내려받는다.</li><li>[Upload] 버튼 : 작성한 Excel·CSV 파일을 선택해 처리한다.</li><li>업로드할 이메일 목록의 미리보기는 제공하지 않는다.</li></ul> |

#### 2-1-2. **업로드 파일 정보·삭제 버튼**

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 2-1-2-1 | 파일 처리 중 | <ul><li>파일명·형식·크기를 표시한다.</li><li>결과 영역을 스켈레톤으로 표시한다. 이메일 배열이나 처리 중 개별 행은 표시하지 않는다.</li><li>파일 삭제와 [Save] 버튼을 비활성화한다.</li></ul> |
| Case 2-1-2-2 | 정상 검증 완료 | <ul><li>파일명·형식·크기와 파일 삭제 버튼을 표시한다.</li><li>아래 결과 영역에 성공·실패 건수를 표시한다.</li><li>파일 삭제 버튼 : 현재 업로드 결과를 제거하고 업로드 전 상태로 돌아간다. 이미 저장된 명단은 삭제하지 않는다.</li></ul> |

- 파일 전송·파싱 자체가 실패한 경우 성공 0건 결과로 표시하지 않는다. 해당 오류 안내·재시도는 기존 파일 업로드 오류 처리와 연결하며, 새 비동기 처리 구조에 따른 복구 상태는 개발 확인 후 이 영역에 적용한다.

### 2-2. **성공·실패 결과 영역**

- 성공·실패 건수 앞에 각각 체크·X 아이콘을 표시한다. 아이콘은 조작 버튼이 아니다.
- 성공 건의 이메일 목록 및 검색 기능은 생성·수정 업로드 단계에서 제공하지 않는다. 저장 후 캠페인 상세의 이메일 관리에서 조회한다.

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 2-2-1 | 실패 0건 | <ul><li>성공·실패 건수를 표시한다.</li><li>실패 파일 다운로드와 성공 건 등록 안내는 표시하지 않는다.</li></ul> |
| Case 2-2-2 | 실패 1건 이상 | <ul><li>실패 건수 옆에 파일 다운로드 아이콘 버튼을 표시한다.</li><li>‘성공한 이메일만 등록됩니다.’ 안내를 결과 영역에 표시한다.</li><li>다운로드 버튼 : 실패한 이메일을 업로드 양식과 같은 형식의 파일로 내려받는다.</li><li>성공 0건인 경우에도 실패 파일을 내려받거나 파일을 제거한 뒤 다시 업로드할 수 있다.</li></ul> |

- 실패 파일은 해당 업로드 단계에서만 제공한다. 저장 완료 후 캠페인 상세에 이전 실패 파일 다운로드를 노출하지 않는다.
- 기존 명단에 등록된 이메일은 성공 건수에 포함하고 실패 파일에서 제외한다. 파일 전체 오류는 [정책 2절](../policy/Policy_05_Hand_raiser.md#2-파일-업로드와-결과-판정)의 개발 확인 기준을 따른다.

### 3-1. **Save 버튼**

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 3-1-1 | 미업로드 또는 정상 검증 성공 0건 | <ul><li>Hand Raiser 명단을 이유로 [Save]를 비활성화하지 않는다. 다른 캠페인 필수값·검증은 기존 기준을 적용한다.</li><li>저장 시 새 이메일은 추가되지 않는다. 수정 중 기존 명단은 유지한다.</li></ul> |
| Case 3-1-2 | 정상 검증 성공 1건 이상 | <ul><li>[Save] 버튼 : 캠페인 저장과 함께 성공한 이메일을 반영한다.</li><li>저장 완료 후 기존 캠페인 저장 후속 동작을 따른다.</li><li>실패한 이메일은 등록하지 않는다.</li></ul> |
| Case 3-1-3 | 파일 처리 중 | <ul><li>[Save] 버튼을 비활성화한다.</li></ul> |

- 추가 업로드 팝업의 ‘성공 1건 이상일 때만 저장 활성화’ 조건을 캠페인 자체의 저장 조건으로 확대하지 않는다.

- 명단 필수 여부나 시스템 실패를 정상 저장으로 해석하지 않는다.
