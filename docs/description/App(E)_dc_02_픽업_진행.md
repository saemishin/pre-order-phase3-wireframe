# 앱 픽업 진행 · 직원 모드

진입 경로: Android 앱 > 직원 모드 > Pre-order > 수령 > 주문 조회 > 기존 주문 확인·수령 절차 > 픽업 진행

---

- 기존 화면 구성을 유지하고 [주문 및 픽업 처리 정책](../policy/Policy_06_주문_및_픽업_처리.md#3-픽업-기간과-진입-가능-여부)의 수령 진입 조건과 기기 식별정보 중복 검증을 적용한다.
- 주문 조회 이후의 주문 정보 확인·수령 방식·약관·인증 등 기존 절차를 유지한다. 와이어프레임에서 생략한 중간 화면을 실제 기능에서도 제거하는 것이 아니다.
- 기간 밖 차단 팝업·토스트의 문구와 기존 동작은 유지한다.

## 1. **캠페인·Batch 목록 화면**

### 1-1. **상단 내비게이션·수령 버튼**

- 기존 `Pre-order` 제목·뒤로 버튼과 우측 `수령` 버튼의 위치·양식을 유지한다.
- 공통 수령 버튼의 기간 조건에 종료일시를 함께 적용한다. 판단 범위는 회사 전체 Batch이며 직원 배정 범위로 축소하지 않는다.
- 미삭제·확정 캠페인, 미삭제 Batch 및 앱 목록 항목 존재 등 기존 조건을 함께 적용한다.

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 1-1-1 | 기존 조건을 충족하고 현재 픽업 기간인 Batch가 하나 이상 있음 | <ul><li>수령 버튼을 표시한다.</li><li>선택 시 기존 주문 바코드 스캔 화면으로 진입한다.</li></ul> |
| Case 1-1-2 | 현재 픽업 기간인 Batch가 없음 | <ul><li>수령 버튼을 표시하지 않는다. 비활성 버튼으로 남기지 않는다.</li><li>모두 픽업 시작 전이거나 모두 종료된 경우를 포함한다.</li></ul> |
| Case 1-1-3 | 종료일시가 없는 Batch가 시작일시를 지났고 기존 조건을 충족함 | <ul><li>기존 종료일 미설정 기준에 따라 수령 버튼을 표시한다.</li></ul> |

- 기간의 시작·종료 경계와 시간대는 정책을 따른다. 별도의 자동 갱신 기능은 추가하지 않는다.

### 1-2. **전체 개수·캠페인 및 Batch 카드**

- 기존 전체 개수와 캠페인·Batch별 카드 구성을 유지한다.
- 캠페인명·이미지·Batch명·기존 상태 표시·주문 및 수령 기간을 기존 기준으로 표시한다.
- 카드의 조회 범위·정렬·선택 후 기존 주문 흐름은 변경하지 않는다. 수령 버튼 조건을 카드 조회 조건으로 추가하지 않는다.

## 2. **주문 조회 화면**

### 2-1. **바코드 스캔 영역·기존 진입 버튼**

- 기존 스캔 영역과 `주문 영수증에 있는 바코드를 스캔하세요.` 안내를 유지한다.
- `주문 코드 직접 입력`, `주문 영수증을 찾을 수 없나요?` 버튼과 연결 흐름을 유지한다.
- 닫기 동작과 바코드 인식 후 주문 조회 방식을 유지한다.

### 2-2. **주문 코드 입력란·확인 버튼**

- 기존 주문 코드 입력란, 형식 안내와 확인 버튼을 유지한다.
- 입력·활성화·조회 동작은 기존과 동일하다. 정상 조회 후 기존 주문 확인·수령 절차로 진행한다.

### 2-3. **기간 밖 조회 시 기존 안내 팝업**

- 조회하려는 주문이 속한 Batch의 픽업 기간이 아니면 기존 조회 차단을 유지한다. 공통 수령 버튼이 표시됐다는 이유로 주문별 검증을 생략하지 않는다.
- 바코드 스캔·주문 코드 직접 입력 모두 기존 주문 미발견 안내를 사용한다.
- 제목: `해당 주문을 찾을 수 없습니다.`
- 본문: `주문 코드를 다시 확인해주세요.`
- 확인 버튼 선택 시 기존처럼 바코드 스캔 화면으로 돌아간다.
- 픽업 시작 전·종료 후 모두 기존 문구를 유지하며, 기간 전용 문구나 새 안내 화면을 추가하지 않는다.

## 3. **기기 정보 입력 1/2 화면**

### 3-1. **상단 내비게이션**

- 기존 `1/2` 단계 표시와 뒤로 버튼을 유지한다.
- 뒤로 선택 시 기존 이전 수령 절차로 돌아가는 동작을 유지한다.

### 3-2. **선택 상품 영역**

- 주문한 상품의 이미지·제품명·SKU·가격을 기존 구성으로 표시한다.
- 기존 상품 이미지·가격 표시 동작을 유지한다.

### 3-3. **기기 식별정보 입력란·스캔 버튼**

- 상품 카테고리 설정에 따라 IMEI 1·IMEI 2·S/N 입력란을 기존 순서와 필수 여부로 제공한다. 모든 상품에 세 항목을 일괄 노출하거나 필수로 변경하지 않는다.
- 각 입력란 우측의 기존 스캔 버튼과 스캔값 반영 동작을 유지한다.
- 중복 오류는 해당 입력란의 기존 오류 스타일과 하단 문구 `이미 등록된 번호입니다.`로 표시한다. 여러 항목이 중복이면 각 항목에 표시한다.
- 오류가 표시된 값을 직접 수정하거나 스캔으로 변경하면 해당 항목의 중복 오류를 해제하고 기존 입력 검증을 적용한다. 다른 항목의 오류·입력값은 유지한다.
- 값을 바꿨다는 이유만으로 서버 중복 검증을 통과한 것으로 처리하지 않는다. 다음 버튼 선택 시 변경된 값으로 다시 확인한다.

### 3-4. **하단 다음 버튼**

- 기존 필수값·입력 유효성에 따른 활성화 조건을 유지한다.
- 다음 선택 시 기존 검증과 함께 정책에 따른 서버 중복 검증을 수행한다. 입력란마다 새 확인 버튼을 추가하지 않는다.

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 3-4-1 | 기존 검증과 중복 검증을 모두 통과함 | <ul><li>기존 내용 확인 2/2 화면으로 이동한다.</li></ul> |
| Case 3-4-2 | IMEI 1·IMEI 2·S/N 중 중복 항목이 확인됨 | <ul><li>1/2 화면에 머무르며 입력값을 유지한다.</li><li>해당 입력란에 기존 중복 오류를 표시한다.</li><li>오류가 남아 있으면 기존 유효성 조건에 따라 다음 버튼을 비활성화한다.</li></ul> |
| Case 3-4-3 | 중복 오류가 있던 값을 수정·스캔으로 변경함 | <ul><li>기존 활성화 조건을 충족하면 다음 버튼을 다시 활성화한다.</li><li>다음 선택 시 현재 입력값으로 중복을 다시 검사한다.</li><li>재검사 결과에 따라 Case 3-4-1 또는 Case 3-4-2로 처리한다.</li></ul> |

## 4. **내용 확인 2/2 화면**

### 4-1. **상단 내비게이션·상품 정보**

- 기존 `2/2` 표시·뒤로 버튼과 상품 이미지·제품명·SKU·가격을 유지한다.
- 뒤로 선택 시 기존 기기 정보 입력 1/2 화면으로 돌아간다.

### 4-2. **기기 정보·고객 정보·안내 영역**

- 입력한 기기 식별정보, Hand raiser 여부와 캠페인에 따른 기존 추가 정보·고객 정보를 기존 구성으로 표시한다.
- 기존 안내 `모든 정보가 정확한지 확인한 후, 고객에게 서명을 요청하세요.`를 유지한다.

### 4-3. **서명 영역·삭제 버튼**

- 기존 서명 입력·삭제 동작과 서명 여부에 따른 완료 조건을 유지한다.
- 최종 중복 검증으로 1/2에 돌아갔다가 다시 2/2로 진입하는 경우 기존 입력 정보와 서명을 유지한다.

### 4-4. **하단 완료 버튼·기존 오류 안내**

- 기존 완료 버튼 활성화 조건과 최종 검증을 유지한다.
- 1/2에서 중복 검증을 통과해도 최종 서버 중복 검증을 생략하지 않는다.
- 해당 주문이 속한 Batch의 픽업 기간도 기존처럼 최종 완료 시 확인한다.

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 4-4-1 | 중복·기간 검증 및 기존 완료 조건을 모두 충족함 | <ul><li>기존 픽업 저장·완료 흐름으로 진행한다.</li></ul> |
| Case 4-4-2 | 최종 검증에서 기기 식별정보 중복이 확인됨 | <ul><li>픽업을 완료하지 않고 기존처럼 1/2 화면으로 돌아간다.</li><li>해당 항목에 `이미 등록된 번호입니다.` 오류를 표시한다.</li><li>다른 입력값과 서명을 유지한다.</li><li>값 수정 후 다음·완료에서 다시 검증한다.</li></ul> |
| Case 4-4-3 | 완료 시 해당 주문의 Batch가 픽업 기간 밖임 | <ul><li>기존 검증으로 픽업 완료를 차단한다.</li><li>`알 수 없는 에러가 발생했습니다. 잠시 후 다시 한 번 시도해보세요.` 공통 오류 토스트를 유지한다.</li><li>기존처럼 현재 2/2 화면과 입력 상태를 유지한다.</li></ul> |

- 토스트의 표시 방식·노출 시간은 기존 앱 공통 기준을 따른다. 기간 전용 문구로 변경하지 않는다.
