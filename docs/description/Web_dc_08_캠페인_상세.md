# 캠페인 상세

진입 경로: 대시보드 > pre-order > 캠페인 상세

---

- 캠페인 상세의 Hand Raiser 명단 영역(P06)과 일반 리더의 설정 정보·주문·실적 조회 및 수정 진입 제한(P04-A)을 다룬다. 주문·실적의 조회 범위는 [권한 및 조회 범위 정책](../policy/Policy_02_권한_및_조회_범위.md)을 따른다.
- 명단 관리 범위는 [Hand Raiser 정책](../policy/Policy_05_Hand_raiser.md)을 따른다. 명단 변경 기능에는 기존 캠페인 관리 권한을 적용하며 일반 조회 권한을 편집 권한으로 해석하지 않는다.

## 1. **캠페인 설정 정보 영역**

### 1-1. **기본 정보·Timeline·Product·Allocation**

- Product 영역에는 캠페인에 등록된 프로덕트 그룹을 모두 표시한다(최대 20개).
- 일반 리더에게도 캠페인 설정 정보를 표시한다. 일반 리더라는 이유로 설정 영역 자체를 숨기지 않는다.
- 대상 근무지·구성원 요약은 기존 표시를 유지한다. 특정 근무지의 첫 이름·나머지 개수, 특정 구성원의 첫 이름·아바타·개수, 그룹·직책의 구분·개수를 개수만 표시하는 방식으로 변경하지 않는다.
- 대상 근무지·구성원 전체 목록을 여는 동작은 추가하지 않는다. 구성원 아바타의 프로필 연결에는 기존 공통 구성원 조회 권한을 유지한다.
- 설정 정보 조회 허용은 담당 범위 밖 주문·실적의 조회 허용을 의미하지 않는다. 주문 수치와 실적에는 일반 리더의 담당 구성원 범위를 적용한다.

### 1-2. **영역별 수정 버튼**

- 일반 리더에게 Timeline·Product·Allocation·Hand Raiser 영역의 수정 버튼을 노출하지 않는다. 마우스를 올려도 수정 버튼이 나타나지 않으며 수정 화면으로 진입할 수 없다.
- 관리자·별도 pre-order 권한 리더의 기존 캠페인 수정 권한과 진입 동작은 유지한다. 이번 조회 허용으로 작업 권한을 새로 부여하지 않는다.

## 2. **Hand Raiser 명단 영역**

- 아래 명단 상태별 버튼 제공 조건은 기존 캠페인 관리 권한이 있는 사용자에게 적용한다. 일반 리더는 개수·최근 업데이트 시각만 조회하며 이메일 관리·추가 업로드 버튼은 노출하지 않는다.

| 케이스 | 조건 | 명세 |
| --- | --- | --- |
| Case 2-1 | 등록된 이메일 1건 이상 | <ul><li>현재 총개수를 표시한다. 최근 업데이트 시각은 2-2의 표시 조건을 따른다.</li><li>이메일 관리·추가 업로드 진입 버튼을 제공한다.</li></ul> |
| Case 2-2 | 등록된 이메일 0건 | <ul><li>0개를 표시하고 최근 업데이트 영역은 노출하지 않는다. 미등록·전체 삭제 여부와 무관하게 동일하게 적용한다.</li><li>이메일 관리 진입은 비활성화하고 추가 업로드는 제공한다.</li></ul> |

### 2-1. **등록 이메일 개수**

- Hand Raiser 영역의 Customer Info 아래 등록된 이메일 총개수를 `N개`로 표시한다. 천 단위 구분자를 사용한다.
- 대표 이메일·첫 이메일 및 나머지 개수 배지는 표시하지 않는다. 명단 전체를 펼쳐 보여주지 않는다.

- 이메일 삭제 또는 추가 업로드 저장에 성공하면 현재 명단 총개수를 갱신한다. 실제 저장된 명단을 기준으로 하며 업로드 파일의 전체 행 수를 그대로 더하지 않는다.

- 취소·조회·검색·파일 처리만으로 등록 개수나 저장된 업데이트 시각을 변경하지 않는다.

### 2-2. **최근 업데이트 시각**

- 기능 적용 이후 실제 추가·삭제가 있었고 등록된 이메일이 1건 이상일 때 총개수 아래에 최근 업데이트 시각을 `yyyy.mm.dd(요일) hh:mm` 형식으로 표시한다.

- 기존 명단은 과거 변경 시각의 기록 여부와 관계없이 최근 업데이트 영역을 숨긴다. 기능 적용 이후 이메일이 실제로 추가되거나 삭제되면 변경이 저장된 시각으로 갱신한다. 이미 등록된 이메일만 업로드한 경우에는 기존 표시 상태와 시각을 유지한다.

- 등록된 이메일이 0건이면 최근 업데이트 레이블과 시각을 모두 노출하지 않는다. 전체 삭제로 0건이 된 경우도 동일하다. 저장된 업데이트 시각을 삭제하는 의미는 아니다.

### 2-3. **이메일 관리·추가 업로드 버튼**

- 기존 캠페인 관리 권한이 있는 사용자에게 총개수 오른쪽의 검색 아이콘과 추가 [+] 아이콘 버튼을 제공한다. 일반 리더에게는 두 버튼 모두 노출하지 않는다.
- 검색 아이콘 : [이메일 관리 팝업](Web_dc_09_Hand_raiser_명단_관리.md#1-이메일-관리-팝업)을 연다.
- 추가 [+] 아이콘 : [추가 업로드 팝업](Web_dc_09_Hand_raiser_명단_관리.md#3-추가-업로드-팝업)을 연다.
- 팝업 뒤 캠페인 상세 화면은 유지한다. 명단 변경을 위해 상세 화면에 별도 저장 버튼을 추가하지 않는다.

- 성공 토스트와 팝업 유지·종료는 [명단 관리 디스크립션](Web_dc_09_Hand_raiser_명단_관리.md)을 따른다.

## 3. **Summary by platform 영역**

### 3-1. **집계 표**

- 기존 접기·펼치기, 플랫폼 합계·프로덕트 그룹 행과 Batch별 Pre-order·Pickup·Pickup% 열 구성을 유지한다.
- 관리자·별도 조회 권한 리더는 기존 전체 범위, 일반 리더는 담당 구성원의 주문 범위로 주문·픽업 수치와 Pickup%를 산출한다.
- 하단 주문 실적·목록의 검색·필터와 독립적으로 집계하는 기존 구조를 유지한다. 하단 필터 결과가 없어도 상단 표를 함께 비우지 않는다.
- 시작된 Batch에서 조회 가능한 주문이 없는 경우 0으로 표시하며, 시작 전·미존재 Batch의 기존 표시 규칙을 유지한다.

### 3-2. **다운로드 메뉴**

- 기존 Image·Excel 메뉴를 유지한다. 일반 리더의 다운로드에도 화면의 담당 구성원 주문 범위를 적용한다.

## 4. **주문 실적 영역**

### 4-1. **기간·근무지·상품 필터**

- 기존 필터 종류·후보 목록·선택 동작을 유지한다. 일반 리더에게도 후보 목록을 별도 축소하지 않는다.
- 아래 실적과 주문 목록에 같은 검색·필터 조건을 적용한다. 필터로 담당 구성원 밖 주문이 조회되지 않는다.

### 4-2. **실적 카드**

- Pre-order Unit·Pre-order Amount·Picked-up Unit 카드 및 Offline 비율 표시 구성을 유지한다.
- 카드의 주문·픽업 실적은 조회 권한 범위와 기존 검색·필터 조건을 적용해 산출한다.
- 주문 수량·금액의 Offline 비율은 기존 배정 수량·금액을 분모로 유지한다. 일반 리더에게 담당 구성원별 배정값을 새로 산출하지 않는다.
- 픽업의 Offline 비율은 같은 조회 범위·검색·필터에 해당하는 오프라인 주문 수량을 분모로 사용한다.
- 분모가 0일 때의 기존 비율 표시를 유지한다.

## 5. **주문 목록 영역**

- 기존 주문 실적 아래의 목록 구성과 컬럼·검색·필터·정렬·페이지 이동 동작을 유지한다. 일반 리더의 접근 허용에 따라 조회 대상 주문과 다운로드 범위를 적용한다.
- 관리자·별도 pre-order 조회 권한 리더는 기존 전체 범위를 조회한다. 일반 리더는 관리 그룹·하위 그룹 구성원이 판매 담당자로 기록된 주문을 현재 소속 기준으로 조회한다. 일괄 등록 주문 제외, 퇴사·삭제 구성원 및 소속 판정 불가 주문은 [권한 및 조회 범위 정책](../policy/Policy_02_권한_및_조회_범위.md)을 따른다.

### 5-1. **전체 개수·검색창**

- 전체 개수는 조회 권한 범위에 현재 검색·필터 조건을 적용한 주문 건수로 표시한다. 현재 페이지의 행 수나 권한 범위 밖 주문을 포함한 전체 건수로 표시하지 않는다.
- 검색 대상·입력·초기화 동작은 기존 기준을 유지한다. 검색어를 변경하거나 지워도 일반 리더의 담당 구성원 범위를 벗어나는 주문은 조회하지 않는다.
- 검색 결과를 하단 주문 실적과 목록에 동일하게 적용하며, 상단 Summary by platform은 기존 독립 집계 구조를 유지한다.

### 5-2. **일괄 작업·다운로드 버튼**

- 일괄 작업 버튼의 기존 관리자 계열 권한을 유지한다. 별도 pre-order 조회 권한 리더와 일반 리더에게 일괄 등록·수정 권한을 추가하지 않는다.
- [일괄 업로드] 선택 시 기존 [일괄 주문 등록 화면](Web_dc_11_일괄_주문_등록.md)으로 이동한다. [일괄 수정]의 기존 진입은 유지한다.
- 일반 리더에게도 다운로드 버튼을 제공한다. 조회 결과가 0건이면 기존처럼 비활성화한다.
- 다운로드 대상은 조회 권한 범위와 현재 검색·필터 조건에 맞는 전체 주문이다. 현재 페이지에 표시된 행으로만 제한하지 않는다.
- 일반 리더의 다운로드 파일에서는 고객 전화번호·이메일 주소·신분증 번호의 세 열 자체를 제외한다. 전화번호에 결합된 국가번호도 함께 제외한다. 그 밖의 파일 양식과 관리자·별도 조회 권한 리더의 기존 다운로드는 유지한다.

### 5-3. **주문 표·컬럼 필터**

- 기존 Product·Order code·Platform·Distributor·Store·Order date·Order status 컬럼과 표시 순서를 유지한다. 상품명·SKU 표시, 가로 스크롤과 상품 열 고정도 유지한다.
- 기존 목록에 없는 고객 전화번호·이메일 주소·신분증 번호 컬럼을 추가하지 않는다. 개인정보 비노출은 해당 정보를 제공하는 주문 상세와 다운로드 파일에 적용한다.
- 플랫폼·주문 상태 필터, 필터 초기화와 주문일시 정렬은 기존 동작을 유지한다. 필터 후보를 일반 리더의 담당 구성원 기준으로 별도 축소하지 않는다.
- 상단 기간·근무지·상품 조건과 목록의 검색·컬럼 필터를 조회 권한 범위 안에서 적용한다. 다른 근무지나 플랫폼을 선택해도 담당 범위 밖 주문이 조회되지 않는다.
- 주문 행을 선택하면 해당 주문의 [주문 상세 모달](Web_dc_01_주문_상세.md)을 연다. 조회 범위와 상세의 고객 정보·작업 버튼 권한을 구분하여 적용한다.

### 5-4. **빈 상태**

- 실제 주문이 없는 경우와 일반 리더에게 조회 가능한 주문이 없는 경우를 구분하지 않고 기존 빈 상태를 표시한다. 권한 밖 주문의 존재나 건수는 안내하지 않는다.
- 검색·필터에 맞는 주문이 없는 경우에도 기존 결과 없음 처리를 유지한다. 조회 오류는 정상적인 0건과 구분하여 기존 오류 처리를 적용한다.

### 5-5. **페이지 이동 영역**

- 기존 페이지 크기 선택·페이지 이동·조회 조건 변경 시 페이지 초기화 동작을 유지한다. 페이지 수는 조회 권한 범위와 검색·필터에 맞는 주문 건수로 산출한다.
- 조회 결과가 0건이면 페이지 이동 영역을 표시하지 않는 기존 동작을 유지한다.
